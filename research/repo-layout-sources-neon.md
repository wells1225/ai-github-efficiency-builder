## 1. Findings

*(Date reference: November 2026. Sources published before November 2025 are explicitly marked as older than 12 months.)*

### A. New Repositories: Day-One Layout for Coding Agents

#### A.1 Instruction Files & the `AGENTS.md` Standard
* **`AGENTS.md` is the cross-tool open standard stewarded by the Agentic AI Foundation under the Linux Foundation.** It is plain Markdown with no required schema or frontmatter, used by over 60,000 open-source repositories, and supported natively (or via a one-line config/import) by Codex, Claude Code, Cursor, Gemini CLI, Amp, Devin, GitHub Copilot coding agent, and Aider.
  * URL: https://agents.md/ and https://raw.githubusercontent.com/agentsmd/agents.md/main/README.md | Publisher: AGENTS.md / Agentic AI Foundation (Linux Foundation) | Date: 2025–2026 (live site) | Label: **documented**
* **Claude Code reads `AGENTS.md` natively (v2.1.277+) only when no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` exists in the working directory or ancestors.** If a repository needs Claude-specific rules or must support older/restricted sessions (e.g., before v2.1.281 on Bedrock), Anthropic documents keeping `AGENTS.md` as the single source of truth and placing `@AGENTS.md` in a root `CLAUDE.md` (which never causes double-loading); symlinks are discouraged for Windows clones because Git checks them out as plain text unless `core.symlinks` is enabled and Claude's Edit/Write tools refuse to write through symlinks.
  * URL: https://code.claude.com/docs/en/memory | Publisher: Anthropic | Date: 2026 (live docs) | Label: **documented**
* **Path-scoped and nested instruction files prevent monorepo and multi-stack context pollution across major tools.** Claude Code (`.claude/rules/*.md` with `paths:` frontmatter, plus lazy subdirectory `CLAUDE.md`/`AGENTS.md`), Cursor (`.cursor/rules/*.mdc` with `globs:`/`description`/`alwaysApply`, plus nested `AGENTS.md`), Amp (subtree `AGENTS.md` plus `@`-mentioned files with `globs:` YAML frontmatter), GitHub Copilot (`.github/instructions/**/*.instructions.md` with `applyTo:` and optional `excludeAgent:`, plus nested `AGENTS.md`), Gemini CLI (JIT `GEMINI.md` in accessed directories), and Devin CLI (lazy subdirectory `AGENTS.md` and `.devin/rules/*.md`) all defer area-specific guidance until the agent works in that area.
  * URLs: https://code.claude.com/docs/en/memory, https://cursor.com/docs/rules, https://ampcode.com/docs/customize/agents-md, https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions, https://geminicli.com/docs/cli/gemini-md/, https://docs.devin.ai/cli/extensibility/rules.md | Publisher: Anthropic, Cursor, Sourcegraph/Amp, GitHub, Google, Cognition | Date: 2026 (live docs; Gemini CLI updated June 18, 2026) | Label: **documented**
* **OpenAI Codex loads `AGENTS.md` from root down to the launch `cwd` once per run and stops at `project_doc_max_bytes` (32 KiB default).** Within each directory it picks at most one non-empty file in precedence order: `AGENTS.override.md`, then `AGENTS.md`, then `project_doc_fallback_filenames`.
  * URL: https://learn.chatgpt.com/docs/agent-configuration/agents-md | Publisher: OpenAI | Date: 2026 (live docs) | Label: **documented**

#### A.2 What Belongs in the Root Instruction File, What Does Not, and Measured Length Effects
* **Only include non-discoverable facts, verification commands, and recurring pitfalls—omit architecture essays, file listings, and full style guides.** Anthropic's test is: *"Could it find this by reading the code? Would it actually go and look? If both are yes, leave it out."* Cursor similarly advises against copying style guides ("Use a linter instead"), documenting standard tools (`npm`, `git`, `pytest`), or duplicating code that can be referenced.
  * URLs: https://code.claude.com/docs/en/best-practices and https://cursor.com/docs/rules | Publisher: Anthropic; Cursor | Date: 2026 (live docs) | Label: **documented**
* **Keep root instruction files short (~60–200 lines) and use them as a table of contents rather than an encyclopedia.** Anthropic targets under 200 lines per `CLAUDE.md` file ("Longer files consume more context and reduce adherence"), OpenAI keeps its root `AGENTS.md` to ~100 lines pointing to structured `docs/`, Devin warns that "Rules and AGENTS should be kept as small as possible" (and truncates automatic injection at 16 KiB), and HumanLayer keeps its root `CLAUDE.md` under 60 lines.
  * URLs: https://code.claude.com/docs/en/memory, https://openai.com/index/harness-engineering/, https://docs.devin.ai/onboard-devin/agents-md, https://docs.devin.ai/cli/extensibility/rules.md, https://www.humanlayer.dev/blog/writing-a-good-claude-md | Publisher: Anthropic (2026); OpenAI (Feb 11, 2026); Cognition (2026); HumanLayer (Nov 25, 2025) | Label: **documented** (Anthropic, OpenAI, Cognition) / **opinion** (HumanLayer)
* **LLM-generated context files lowered task resolution rates while raising cost by >20%; human-written files helped only marginally (+4% avg, +≤19% cost) and did not speed up file discovery.** Across four coding agents on SWE-bench Lite and AGENTbench (138 instances across 12 repos), ETH Zurich / LogicStar.ai measured that LLM-generated context files reduced average resolution by 0.5% on SWE-bench Lite and 2% on AGENTbench (with 20% and 23% higher cost and +2.45 / +3.92 steps), and that repository overviews in context files did not reduce steps-to-first-relevant-file—except when all other repo docs were deleted (+2.7% gain).
  * URL: https://arxiv.org/html/2602.11988v1 | Publisher: ETH Zurich & LogicStar.ai (Gloaguen et al.) | Date: February 12, 2026 | Label: **measured**
* **Instruction adherence degrades systematically as instruction count grows, and longer input contexts degrade recall ("context rot").** IFScale tested 20 frontier models from 10 to 500 simultaneous instructions and found even the best frontier models reached only 68% accuracy at 500 instructions, with primacy bias peaking around 150–200 instructions and reasoning-model latency surging (e.g., `o4-mini` from 12.40s at 10 instructions to 436.19s at 250). Chroma tested 18 models across controlled input lengths and showed non-uniform degradation as context length and distractors grow.
  * URLs: https://arxiv.org/html/2507.11538v1 and https://www.trychroma.com/research/context-rot | Publisher: Distyl AI (Jaroslawicz et al.), July 15, 2025 *(older than 12 months)*; Chroma Research (Hong et al.), July 14, 2025 *(older than 12 months)* | Label: **measured**
* **For framework/API knowledge absent from model training data, a compressed passive index in `AGENTS.md` outperformed on-demand skills.** In Vercel's Next.js 16 API evals, an 8 KB pipe-delimited docs index embedded in `AGENTS.md` (pointing to `.next-docs/`) achieved a 100% pass rate versus 53% baseline, 53% for default skills (never triggered in 56% of cases), and 79% for skills with explicit trigger instructions.
  * URL: https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals | Publisher: Vercel (Jude Gao) | Date: January 27, 2026 | Label: **measured**

#### A.3 Folder Structure (Domain vs. Layer, Monorepo vs. Polyrepo, Tests)
* **Strict domain boundaries with mechanically enforced forward-only layer dependencies let agents ship rapidly without architectural drift.** In OpenAI's 1M-LOC Codex-built codebase, each business domain has a fixed forward dependency chain (`Types -> Config -> Repo -> Service -> Runtime -> UI`), with cross-cutting concerns entering only through an explicit `Providers` interface, enforced by custom linters and structural tests.
  * URL: https://openai.com/index/harness-engineering/ | Publisher: OpenAI (Ryan Lopopolo) | Date: February 11, 2026 | Label: **opinion** (experience report)
* **Monorepos eliminate cross-repo "Read, Write, and Memory" walls for agents, provided per-package context is scoped.** Nx reports a side-by-side cross-project agent demo completing 4× faster with an estimated 1/3 reduction in total effort in a monorepo because agents can inspect consumers, edit atomically in one PR, and validate all affected projects together. Conversely, Anthropic warns that in large monorepos default root-level loading fills context with unrelated packages and documents launching in package subdirectories, per-package `CLAUDE.md`, `claudeMdExcludes`, and `worktree.sparsePaths`.
  * URLs: https://nx.dev/blog/the-effect-of-monorepos-on-the-effectiveness-of-ai-agents and https://code.claude.com/docs/en/large-codebases | Publisher: Nx (Victor Savkin), July 22, 2026; Anthropic, 2026 (live docs) | Label: **measured** (Nx demo) / **documented** (Anthropic)
* **No primary agent benchmark settles colocated tests vs. separate `tests/` trees.** Even tool-maker documentation examples differ (Devin's `AGENTS.md` example shows a top-level `/tests` folder, while Claude Code's `.claude/rules` example shows `tests/**/*.test.ts` and Amp's glob example shows both `*.test.ts` and `__tests__/*`).
  * URLs: https://docs.devin.ai/onboard-devin/agents-md, https://code.claude.com/docs/en/memory, https://ampcode.com/docs/customize/agents-md | Publisher: Cognition; Anthropic; Sourcegraph/Amp | Date: 2026 (live docs) | Label: **documented**

#### A.4 File Size, Naming, and Barrel Files
* **Avoid internal barrel files (`index.ts` re-exporting a directory); use direct module imports except at external package public APIs.** Atlassian measured 75% faster builds after removing cascading barrel files from Jira's frontend (where local TypeScript hover previously took up to 2 minutes and single unit tests took minutes because dependency graphs pulled in hundreds of unrelated modules). Marvin Hagemeister and TkDodo document the same module-graph explosion and circular-import hazards (`import/no-cycle`)—both of which directly slow the typecheck and unit-test feedback loops agents run repeatedly.
  * URLs: https://www.atlassian.com/blog/how-we-build/faster-builds-when-removing-barrel-files, https://marvinh.dev/blog/speeding-up-javascript-ecosystem-part-7/, https://tkdodo.eu/blog/please-stop-using-barrel-files | Publisher: Atlassian (Tim Sebastian), June 26, 2025 *(older than 12 months)*; Marvin Hagemeister, October 8, 2023 *(older than 12 months)*; TkDodo, July 26, 2024 *(older than 12 months)* | Label: **measured** (Atlassian) / **opinion** (Hagemeister, TkDodo)
* **Enforce naming consistency and file-size bounds mechanically rather than in prose.** OpenAI statically enforces naming conventions for schemas/types and file-size limits using custom linters whose error messages inject remediation steps into agent context; TkDodo recommends static lint rules like `unicorn/filename-case`.
  * URLs: https://openai.com/index/harness-engineering/ and https://tkdodo.eu/blog/please-stop-using-barrel-files | Publisher: OpenAI (Feb 11, 2026); TkDodo (Jul 26, 2024, *older than 12 months*) | Label: **opinion**

#### A.5 Maps, Indexes, `ARCHITECTURE.md`, `docs/`, `llms.txt`, Repo Maps, and ADRs
* **Keep a short `ARCHITECTURE.md` focused on stable boundaries, invariants, and symbol names (not line links) alongside a versioned `docs/` knowledge base checked by CI.** `matklad` recommends describing coarse-grained modules, invariants ("expressed as an absence of something"), and naming types/modules without direct links that rot; OpenAI pairs a ~100-line `AGENTS.md` map with `ARCHITECTURE.md` and `docs/` (`design-docs/`, `exec-plans/`, `generated/db-schema.md`, `product-specs/`, `references/*-llms.txt`) validated by CI cross-link linters and a recurring "doc-gardening" agent.
  * URLs: https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html and https://openai.com/index/harness-engineering/ | Publisher: Alexey Kladov (`matklad`), Feb 6, 2021 *(older than 12 months)*; OpenAI, Feb 11, 2026 | Label: **opinion**
* **Versioned in-repo execution/progress logs and ADRs preserve the "why" across stateless sessions.** Anthropic's long-running harness uses an initializer-created JSON feature list (`passes: false`, chosen over Markdown because models are less likely to inappropriately overwrite JSON) plus `claude-progress.txt` and git commits so fresh sessions recover state cleanly. ADRs capture architecturally significant decisions and trade-offs so agents and humans do not reverse intentional constraints.
  * URLs: https://www.anthropic.com/research/effective-harnesses-for-long-running-agents and https://adr.github.io/ | Publisher: Anthropic (Nov 26, 2025); ADR GitHub Org (2026) | Label: **opinion**
* **Generated AST/PageRank repo maps and LSP code intelligence replace manual file listings without going stale.** Aider automatically parses the repo with Tree-sitter, ranks symbols via a dependency-graph algorithm, and injects the top ~1k tokens (`--map-tokens 1024`) dynamically; Anthropic recommends language-server code-intelligence plugins (e.g., `typescript-lsp`) in large codebases so Claude jumps to definitions and callers instead of burning reads on grep scans.
  * URLs: https://aider.chat/docs/repomap.html and https://code.claude.com/docs/en/large-codebases | Publisher: Aider (live docs); Anthropic (2026, live docs) | Label: **documented**
* **`llms.txt` is a website documentation index, not a repository instruction file—though vendoring external libraries' `*-llms.txt` into `docs/references/` is an emerging pattern.** The `/llms.txt` v2 spec (adopted by OpenAI, Anthropic, Gemini, Cursor, Amp, and Devin for their own docs) serves clean Markdown indexes over HTTP; OpenAI's Harness Engineering repo checks external tool references (`uv-llms.txt`, `nixpacks-llms.txt`) into `docs/references/`.
  * URLs: https://llmstxt.org/ and https://openai.com/index/harness-engineering/ | Publisher: Jeremy Howard / Answer.AI (Sept 3, 2024; modified Aug 10, 2026); OpenAI (Feb 11, 2026) | Label: **documented** (`llmstxt.org`) / **opinion** (OpenAI)

#### A.6 Cutting Wasted Tokens: Ignore Files, Generated Code, and Targeted Check Commands
* **Honor `.gitignore` first, then layer tool-specific ignore and `Read`-deny rules for checked-in generated, vendored, and secret files.**
  * **Claude Code:** Built-in content searches respect `.gitignore` by default (`respectGitignore` controls the `@` picker). For *checked-in* generated/vendored files or secrets, commit `permissions.deny` rules in `.claude/settings.json` (e.g., `Read(./**/dist/**/*)`, `Read(./**/*.generated.*)`, `Read(./**/vendor/**/*)`, `Read(./.env)`), using `/**/*` so directory listing still works; note deny rules do not catch arbitrary subprocesses unless `/sandbox` is enabled. (https://code.claude.com/docs/en/large-codebases, https://code.claude.com/docs/en/best-practices, https://code.claude.com/docs/en/settings-reference | Anthropic | 2026 | **documented**)
  * **Cursor:** Automatically ignores `.gitignore` plus a large built-in default list (lockfiles, `.env*`, binaries, `node_modules/`, `.next/`, etc.), extendable via root `.cursorignore` (and optional hierarchical `.cursorignore`). Terminal commands and MCP servers bypass `.cursorignore`. (https://cursor.com/docs/reference/ignore-file | Cursor | 2026 | **documented**)
  * **Gemini CLI:** Uses root `.geminiignore` (`.gitignore` glob syntax, requires session restart) alongside `.gitignore`/`.aiexclude` to exclude paths from tools and `@` file sharing. (https://geminicli.com/docs/cli/gemini-ignore/ | Google | Apr 10, 2026 | **documented**)
  * **GitHub Copilot:** Uses repo/org/enterprise Content Exclusions (Business/Enterprise plans), which act as a platform guardrail for Copilot tools and identifiable shell paths—not an OS security boundary. (https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion | GitHub | 2026 | **documented**)
  * **Aider:** Supports `.aiderignore` (`.gitignore` syntax) and `--subtree-only` to keep monorepo clutter out of the repo map and chat. (https://aider.chat/docs/faq.html | Aider | live docs | **documented**)
  * **Amp:** Supports `AMP_IGNORE_GUIDANCE_FILES` to skip guidance files; no separate `.ampignore` file was found on the opened pages. (https://ampcode.com/docs/customize/agents-md | Sourcegraph/Amp | 2026 | **documented**)
* **Document exact one-command validation and single-unit test filters in `AGENTS.md`.** Anthropic calls the check command *"the single most useful line in your `CLAUDE.md`"*, and the official `AGENTS.md` spec example explicitly pairs package-scoped test commands (`pnpm turbo run test --filter <pkg>`) with single-test focus flags (`pnpm vitest run -t "<test name>"`) and package lookup commands (`pnpm dlx turbo run where <pkg>`) to avoid directory scans.
  * URLs: https://code.claude.com/docs/en/best-practices and https://agents.md/ | Publisher: Anthropic; AGENTS.md | Date: 2026 | Label: **documented**

#### A.7 Guard Rails: Deterministic Enforcement & Fast Feedback Loops
* **Promote zero-exception rules out of Markdown and into deterministic harness mechanisms (hooks, deny rules, linters, typecheckers, tests, CI).** Anthropic distinguishes non-deterministic instructions (`CLAUDE.md`, prompts) from deterministic enforcement (`PreToolUse`/`PostToolUse`/`Stop` hooks, `permissions.deny`, sandbox, CI): *"If you keep adding emphasis to a `CLAUDE.md` line and Claude still misses it, that's a sign the line belongs in a hook."*
  * URL: https://code.claude.com/docs/en/best-practices | Publisher: Anthropic | Date: 2026 (live docs) | Label: **documented**
* **Write custom linter error messages to instruct the agent how to fix violations, and give agents end-to-end verification surfaces.** OpenAI writes custom architectural lint error messages as in-context remediation instructions and exposes per-worktree bootable apps, Chrome DevTools snapshots, and local logs/metrics so Codex verifies behavior end-to-end. Anthropic similarly found agents falsely marked features complete after unit/curl checks alone until given browser-automation end-to-end verification.
  * URLs: https://openai.com/index/harness-engineering/ and https://www.anthropic.com/research/effective-harnesses-for-long-running-agents | Publisher: OpenAI (Feb 11, 2026); Anthropic (Nov 26, 2025) | Label: **opinion** (experience reports)
* **Environment readiness (validation, build, testing, docs, dev env, observability, security, task discovery) is the main lever for autonomous agent reliability.** Factory organizes codebase readiness into those 8 technical pillars across 5 maturity levels and automates CI-gated score tracking.
  * URLs: https://factory.com/product/agent-readiness and https://factory.com/articles/measuring-agent-readiness | Publisher: Factory | Date: May 27, 2026 | Label: **documented** / **opinion**

### B. Existing Repositories: Restructuring Safely for Agents

#### B.1 What to Change First (Ordered by Gain for Cost)
* **First, establish fast, reproducible, one-command verification (lint, typecheck, targeted test) and deterministic access/ignore rules—before writing prose or moving folders.** Anthropic identifies a runnable pass/fail check as the highest-leverage single setup item and deterministic hooks/deny rules as required for hard boundaries; Factory's readiness loop similarly targets missing `AGENTS.md`, missing test/validation scaffolding, and undocumented env vars first.
  * URLs: https://code.claude.com/docs/en/best-practices, https://factory.com/product/agent-readiness, https://factory.com/articles/measuring-agent-readiness | Publisher: Anthropic (2026); Factory (May 27, 2026) | Label: **documented** / **opinion**
* **Second, write a minimal human-authored root `AGENTS.md` (not `/init` bloat) and add ignore / `Read`-deny rules for generated, vendored, and secret paths.** ETH Zurich measured that auto-generated context files hurt resolution and add >20% cost, whereas concise human instructions with exact non-standard tooling commands help; Claude Code's `/doctor` checkup explicitly trims discoverable directory layouts and dependency lists.
  * URLs: https://arxiv.org/html/2602.11988v1, https://code.claude.com/docs/en/memory, https://code.claude.com/docs/en/large-codebases | Publisher: ETH Zurich (Feb 12, 2026); Anthropic (2026) | Label: **measured** (ETH Zurich) / **documented** (Anthropic)
* **Third, fix structural bottlenecks that slow feedback loops (e.g., cascading barrel files) and add architectural lints + incremental "garbage collection" PRs.** Atlassian's barrel removal cut build times by 75% and sped up typechecking and test selection; OpenAI replaced weekly manual cleanup ("20% of the week") with small automated refactoring PRs enforcing "golden principles."
  * URLs: https://www.atlassian.com/blog/how-we-build/faster-builds-when-removing-barrel-files and https://openai.com/index/harness-engineering/ | Publisher: Atlassian (Jun 26, 2025, *older than 12 months*); OpenAI (Feb 11, 2026) | Label: **measured** (Atlassian) / **opinion** (OpenAI)

#### B.2 How to Restructure Safely
* **Use AST-based codemods (e.g., `jscodeshift`, OpenRewrite) for large-scale import updates and mechanical API rewrites instead of manual or LLM-only edits.** Juntao Qiu (on `martinfowler.com`) documents test-driven codemods and composing small transformers to apply precise, repeatable structural changes across large codebases.
  * URL: https://martinfowler.com/articles/codemods-api-refactoring.html | Publisher: martinfowler.com (Juntao Qiu) | Date: January 22, 2025 *(older than 12 months)* | Label: **opinion**
* **Use `git mv` in isolated move-only commits and raise `merge.renameLimit` / `diff.renameLimit` when mass-moving files with open PRs.** Git documents `git mv` for moving tracked files/directories and `merge.renameLimit` (defaulting to `diff.renameLimit`) as the cap on files considered during merge rename detection—above which Git stops detecting renames across branches.
  * URLs: https://git-scm.com/docs/git-mv and https://git-scm.com/docs/merge-config | Publisher: Git Project | Date: Git 2.50.0 (June 16, 2025, *older than 12 months*) / live docs | Label: **documented**
* **Keep every migration step small, repeatable, and green via tests/CI.** Devin's migration documentation recommends encoding repeatable migration procedures in reusable skills and running build/test verification on every step (e.g., JS-to-TS or framework upgrades in parallel scoped batches); OpenAI keeps PRs short-lived so regressions are cheap to isolate and fix.
  * URLs: https://docs.devin.ai/use-cases/migration-modernization.md and https://openai.com/index/harness-engineering/ | Publisher: Cognition (2026); OpenAI (Feb 11, 2026) | Label: **documented** / **opinion**

#### B.3 Migrating in Place vs. Rewriting from Scratch
* **Prefer gradual in-place modernization (Strangler Fig) over wholesale rewrites for active production systems.** Martin Fowler warns that full replacements routinely "go down in flames" because existing edge-case behavior is hard to specify and users cannot pause for new features; instead, insert seams, build new behavior alongside legacy code, and replace components incrementally.
  * URL: https://martinfowler.com/bliki/StranglerFigApplication.html | Publisher: Martin Fowler | Date: August 22, 2024 *(older than 12 months)* | Label: **opinion**
* **Greenfield / rewrite-from-scratch works when starting a net-new product with no legacy contract to preserve.** OpenAI's zero-human-code Codex repo succeeded starting from an empty git repository where scaffolding, strict layered boundaries, and observability were designed for agent legibility from commit 1.
  * URL: https://openai.com/index/harness-engineering/ | Publisher: OpenAI (Ryan Lopopolo) | Date: February 11, 2026 | Label: **opinion** (experience report)

### C. Disagreements and Practices That Made Agents Worse

* **Auto-generating `AGENTS.md` / `CLAUDE.md` (`/init`) vs. hand-writing minimal files.** Tool makers promote onboarding/init prompts (Claude Code `/init`, GitHub Copilot's onboarding prompt asking for up to 2 pages including root file lists and code snippets, Amp's auto-generate offer), whereas ETH Zurich measured that LLM-generated context files *decreased* resolution rates (−0.5% to −2%) while increasing cost 20–23%, and HumanLayer explicitly advises *"Don't use `/init` or auto-generate your `CLAUDE.md`."*
  * URLs: https://arxiv.org/html/2602.11988v1, https://www.humanlayer.dev/blog/writing-a-good-claude-md, https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions, https://code.claude.com/docs/en/memory | Publisher: ETH Zurich (Feb 12, 2026); HumanLayer (Nov 25, 2025); GitHub (2026); Anthropic (2026) | Label: **measured** (ETH Zurich) / **documented** & **opinion**
* **Passive always-on context (`AGENTS.md`) vs. on-demand skills.** Devin CLI docs strongly recommend *"using Skills instead whenever possible"* to improve speed and lower cost, and Claude Code docs direct multi-step/task-specific workflows to skills. Yet Vercel measured that default skills were ignored 56% of the time (53% pass rate = no docs), whereas a compressed 8 KB passive docs index in `AGENTS.md` hit 100%—reconciled by Vercel as passive indexes for horizontal framework facts vs. skills for explicit vertical workflows.
  * URLs: https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals, https://docs.devin.ai/cli/extensibility/rules.md, https://code.claude.com/docs/en/memory | Publisher: Vercel (Jan 27, 2026); Cognition (2026); Anthropic (2026) | Label: **measured** (Vercel) / **documented** (Devin, Anthropic)
* **Repository/directory overviews inside `AGENTS.md` / `CLAUDE.md`.** GitHub Copilot's onboarding prompt and Devin's sample `AGENTS.md` include project directory listings, whereas Anthropic's "What you can stop doing" table explicitly says to *stop* describing architecture and file layout in `CLAUDE.md` ("Claude reads the repo itself"), Claude Code's `/doctor` strips directory layouts, and ETH Zurich measured that context-file overviews did not reduce steps to find relevant files.
  * URLs: https://code.claude.com/docs/en/best-practices, https://code.claude.com/docs/en/memory, https://arxiv.org/html/2602.11988v1, https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions | Publisher: Anthropic (2026); ETH Zurich (Feb 12, 2026); GitHub (2026) | Label: **measured** (ETH Zurich) / **documented**
* **Monolithic instruction files, ALL-CAPS emphasis, and prose-enforced hard rules made agents worse.** OpenAI reports their "one big `AGENTS.md`" failed because it crowded out task context, diluted priorities ("When everything is 'important,' nothing is"), and rotted instantly. Anthropic warns that adding `IMPORTANT` or ALL CAPS now makes current models *over-apply* rules, and that prose "never do X" rules fail because models can choose to ignore guidelines (whereas hooks/deny rules enforce deterministically).
  * URLs: https://openai.com/index/harness-engineering/ and https://code.claude.com/docs/en/best-practices | Publisher: OpenAI (Feb 11, 2026); Anthropic (2026) | Label: **opinion** / **documented**
* **Adding all repo files to context, over-using barrel files, and relying on `CLAUDE.md` alongside `AGENTS.md` unintentionally.** Aider warns adding irrelevant files distracts the LLM and can cause failed edits; Atlassian documented cascading barrel files causing multi-minute typechecks/tests (while noting the trade-off of weaker internal encapsulation when removed); Claude Code warns that adding a `CLAUDE.local.md` silently disables default `AGENTS.md` loading unless `Project instructions` is changed to `claude-md-and-agents-md`.
  * URLs: https://aider.chat/docs/faq.html, https://www.atlassian.com/blog/how-we-build/faster-builds-when-removing-barrel-files, https://code.claude.com/docs/en/memory | Publisher: Aider (live docs); Atlassian (Jun 26, 2025, *older than 12 months*); Anthropic (2026) | Label: **documented** / **measured**

## 3. Proposed Standard Layout for a New Repository

Every entry below is backed by an opened source from Sections 1–2:

```text
repo-root/
├── AGENTS.md                        # Concise (~60–150 line, <16 KiB) cross-tool map: build/test/single-unit commands, non-discoverable pitfalls, pointers to docs/ (agents.md, OpenAI Harness, Devin, ETH Zurich, HumanLayer)
├── CLAUDE.md                        # Single line `@AGENTS.md` (plus any Claude-only notes) for compatibility with Claude Code <v2.1.277 / restricted sessions without double-loading or Windows symlink breakage (Claude Code Memory)
├── ARCHITECTURE.md                  # Short bird's-eye codemap of coarse modules, layer boundaries, and invariants naming symbols instead of stale line links (matklad, OpenAI Harness)
├── .gitignore                       # First line of defense excluding build outputs, caches, and secrets from Git, Claude Code grep, Cursor, and Gemini CLI (Claude Large Codebases, Cursor Ignore, Gemini Ignore)
├── .cursorignore                    # Excludes checked-in generated/vendored/sensitive files from Cursor Agent/Tab/indexing beyond .gitignore (Cursor Ignore)
├── .geminiignore                    # Mirrors .cursorignore exclusions for Gemini CLI tools and @ file references (Gemini Ignore)
├── .aiderignore                     # Keeps generated/vendored/irrelevant monorepo subtrees out of Aider's Tree-sitter repo map (Aider FAQ)
├── .aider.conf.yml                  # Sets `read: AGENTS.md` so Aider loads the single shared root instruction file automatically (agents.md, Aider Conventions)
├── .claude/
│   ├── settings.json                # Deterministic enforcement: `permissions.deny` `Read(...)` rules for checked-in generated/vendored/secret paths, plus PostToolUse/Stop hooks for zero-exception checks (Claude Best Practices, Claude Large Codebases)
│   └── rules/                       # Path-scoped `.md` rules (`paths:` YAML frontmatter) for conventions shared across scattered directories (Claude Code Memory)
├── .github/
│   ├── instructions/                # Path-scoped `*.instructions.md` (`applyTo:` frontmatter) only if GitHub Copilot users need Copilot-specific path rules beyond nested AGENTS.md (GitHub Docs)
│   └── workflows/                   # Deterministic CI checks mirroring local one-command scripts (lint, typecheck, architectural boundary tests, doc cross-link checks) (OpenAI Harness, Claude Best Practices, agents.md)
├── docs/                            # Versioned in-repo system of record loaded on demand via progressive disclosure, validated by CI link/freshness checks (OpenAI Harness, HumanLayer)
│   ├── decisions/                   # Immutable Architecture Decision Records (ADRs) explaining why constraints and technology choices exist (adr.github.io)
│   ├── design-docs/                 # Indexed design specs and core engineering principles (OpenAI Harness)
│   ├── exec-plans/                  # Active/completed execution plans and tech-debt tracking for multi-session continuity (OpenAI Harness, Anthropic Long-Running Harnesses)
│   ├── generated/                   # Auto-generated machine-readable references such as `db-schema.md` (OpenAI Harness)
│   └── references/                  # Version-pinned external library docs (e.g., `*-llms.txt` or `.next-docs/` indexed concisely in AGENTS.md) (OpenAI Harness, Vercel, llmstxt.org)
├── packages/                        # Monorepo packages or domain directories; avoids polyrepo Read/Write/Memory walls while allowing per-package scoping (Nx, Claude Large Codebases)
│   └── <domain>/
│       ├── AGENTS.md                # Package/domain-specific commands and gotchas loaded lazily when agents work in this subtree (Claude Memory, Cursor Rules, Amp, Devin CLI, Copilot)
│       ├── types/                   # Strict forward-only domain layers (`types -> config -> repo -> service -> runtime -> ui`) enforced by custom linters; direct imports without internal barrel `index.ts` files (OpenAI Harness, Atlassian, TkDodo)
│       ├── config/                  # Domain configuration layer (OpenAI Harness)
│       ├── repo/                    # Data access layer (OpenAI Harness)
│       ├── service/                 # Business logic layer with explicit boundary validation (OpenAI Harness)
│       ├── runtime/                 # Runtime wiring and provider interfaces for cross-cutting concerns (OpenAI Harness)
│       └── ui/                      # Presentation layer (OpenAI Harness)
└── scripts/                         # Deterministic single-command entrypoints (e.g., bootstrap, lint, typecheck, test-unit, check-all) invoked identically locally and in CI (OpenAI Harness, Anthropic Harnesses, Claude Best Practices)
```

## 4. Proposed Step-by-Step Procedure for Restructuring an Existing Repository

Ordered by highest agent reliability gain per unit of risk and engineering cost:

1. **Standardize one-command verification and single-unit test execution (no code moves yet).**
   * *Action:* Add or expose deterministic commands for format, lint, typecheck, targeted single-file/single-test runs, and full CI check (aligned between local and CI).
   * *Verification check:* Run each command from a clean checkout and confirm identical exit code `0` locally and in CI, and confirm a single-unit test command completes quickly without running the entire suite. *(Sources: Claude Best Practices, agents.md, Factory Agent Readiness)*
2. **Block token waste and secret reads with ignore files and deterministic deny rules.**
   * *Action:* Verify `.gitignore` excludes build/cache outputs; add `.cursorignore`, `.geminiignore`, `.aiderignore`, and `.claude/settings.json` `permissions.deny` `Read(./**/<generated|vendor>/**/*)` + secret rules (plus GitHub Content Exclusions if on Copilot Business/Enterprise).
   * *Verification check:* Run `git check-ignore -v <path>` for `.gitignore`/`.cursorignore` patterns; in Claude Code, verify attempting to read `.env` or a generated file is blocked by `permissions.deny`; in Gemini CLI/Cursor, verify `@` search excludes ignored paths. *(Sources: Claude Large Codebases, Cursor Ignore, Gemini Ignore, GitHub Content Exclusion)*
3. **Write a minimal, human-authored root `AGENTS.md` (<150 lines, <16 KiB) and compatibility shims.**
   * *Action:* Do *not* commit raw `/init` output. Write only non-discoverable build/test/single-unit commands, required env setup, hard gotchas, and pointers to existing docs. Add `CLAUDE.md` containing `@AGENTS.md` (for older/restricted Claude Code sessions) and `.aider.conf.yml` with `read: AGENTS.md` if Aider is used.
   * *Verification check:* Confirm file size (`wc -l AGENTS.md` < 150–200 lines; `wc -c AGENTS.md` < 16,384 bytes for Devin and < 32,768 bytes for Codex); verify loading in each tool (`/context all` or `/memory` in Claude Code, `codex --ask-for-approval never "Summarize the current instructions."`, `/memory show` in Gemini CLI). *(Sources: ETH Zurich, Claude Memory, Codex AGENTS.md, Devin AGENTS.md, Gemini CLI)*
4. **Promote zero-exception rules from prose into deterministic hooks, linters, and CI.**
   * *Action:* Move formatting, protected-path guards (e.g., committed migrations, generated code), and import/cycle rules (`import/no-cycle`, custom boundary lints with remediation messages) into pre-commit/Claude hooks and CI; delete the corresponding prose from `AGENTS.md`.
   * *Verification check:* Introduce a deliberate violation (bad formatting, disallowed import, or edit to a protected path) on a scratch branch and confirm the hook/linter blocks it automatically with an actionable error message. *(Sources: Claude Best Practices, OpenAI Harness, HumanLayer, TkDodo)*
5. **Create a concise `ARCHITECTURE.md` and structured `docs/` index (with CI link checks).**
   * *Action:* Document coarse modules, explicit layer boundaries, and non-obvious invariants in `ARCHITECTURE.md` using symbol names (no line-number links), move deep guides/ADRs into `docs/`, and add a CI check validating internal markdown links and freshness.
   * *Verification check:* CI link-checker passes; a fresh agent session can locate the target module for 3–5 representative issues without scanning unrelated packages. *(Sources: matklad, OpenAI Harness, adr.github.io)*
6. **Eliminate build/typecheck bottlenecks such as cascading internal barrel files via codemods.**
   * *Action:* Write and test an AST codemod (`jscodeshift` / OpenRewrite) to rewrite internal barrel imports to direct module imports package by package, keeping each PR small and green; keep public entrypoints only for published packages.
   * *Verification check:* Typecheck, unit tests, and build pass on every PR; measure before/after typecheck time, single-test startup time, and CI build duration. *(Sources: Atlassian, Marvin Hagemeister, martinfowler.com Codemods)*
7. **Coordinate and execute directory/domain restructuring using pure `git mv` commits and Strangler Fig seams.**
   * *Action:* Coordinate a short merge window for open PRs; configure `git config merge.renameLimit 9999` (and `diff.renameLimit`) during the move; isolate pure `git mv` commits from logic edits; update imports deterministically with codemods; for legacy monoliths, introduce seams and migrate one domain at a time (Strangler Fig) rather than rewriting from scratch; add nested `<domain>/AGENTS.md` files only where a subtree has distinct commands or rules.
   * *Verification check:* `git log --follow <moved-file>` preserves full file history; `git diff --stat -M` detects renames rather than delete+add; full CI suite passes after every step; open feature branches rebase/merge cleanly against `main`. *(Sources: Git `git-mv` & `merge-config`, martinfowler.com Strangler Fig & Codemods, OpenAI Harness)*
8. **Maintain continuously via periodic pruning and "garbage collection."**
   * *Action:* Run `/doctor prompt-audit` (or manual review) on instruction files after major refactors or model upgrades to delete obsolete workarounds; run scheduled cleanup checks for stale docs and architectural drift.
   * *Verification check:* Audit reports zero dead paths/commands or contradictory rules; doc-link and architectural lint CI jobs stay green. *(Sources: Claude Memory, Claude Large Codebases, OpenAI Harness)*

## 5. Unverified Claims and Widely Repeated Claims Lacking Primary Evidence

### Widely Repeated Claims With No Controlled Agent Benchmark Found
1. **"Feature-based folders outperform layer-based folders for AI agents."** Repeated widely across practitioner blogs, and OpenAI's Harness Engineering uses domain-first folders with strict internal layers, but no controlled benchmark measuring agent resolution rate or token cost on feature-vs-layer trees was found.
2. **"Colocated tests (`foo.test.ts` beside `foo.ts`) outperform a separate `tests/` directory for agents."** Widely asserted in practitioner posts, but unmeasured in primary research; official tool examples themselves split between colocated and top-level `tests/` layouts.
3. **"Keep every source file under 200–300 lines specifically for LLMs."** Cursor's docs recommend `<500 lines` for *rule files* (and include a React example mentioning `<200 lines` for components), and OpenAI enforces custom file-size lints without disclosing a threshold, but no controlled study measuring source-file LOC against coding-agent edit accuracy was found.
4. **"Duplicate filenames (`index.ts`, `utils.ts`) measurably increase LLM grep/search failure rates."** While barrel files (`index.ts`) have strong *measured* build, typecheck, and test-runner penalties (Atlassian, 75% faster builds), no primary benchmark was found quantifying grep-token waste from duplicate filenames on agent pass rates.
5. **"Per-folder `README.md` files or ADRs measurably improve coding-agent pass rates."** Conceptually supported by practitioners and OpenAI's `docs/` architecture, yet ETH Zurich's controlled study found redundant repository overviews in context files did *not* reduce steps to find relevant files and increased cost; no controlled agent benchmark for per-folder READMEs or ADRs was found.

### Tool/Source Details That Could Not Be Verified From Opened Primary Docs
1. **OpenAI Codex ignore file:** No `.codexignore` mechanism was documented on the opened Codex pages (`learn.chatgpt.com/docs/agent-configuration/agents-md` and `config-advanced`).
2. **Amp ignore file & size cap:** Opened Amp docs (`ampcode.com/docs/customize/agents-md`) document `AMP_IGNORE_GUIDANCE_FILES` for skipping guidance files, but do not document a `.ampignore` file for repo search or a hard byte/character cap on `AGENTS.md`.
3. **Gemini CLI hard context-file size limit:** Opened pages (`geminicli.com/docs/cli/gemini-md/` and `reference/memport/`) document a default import depth limit of 5, but do not state a hard byte/character limit for `GEMINI.md`. (Note: Gemini CLI's site also displays a banner noting that for unpaid/Google One tiers it was replaced by Antigravity CLI on June 18, 2026.)
4. **GitHub Copilot coding agent hard size cap & import syntax:** Opened GitHub Docs state a "no longer than 2 pages" target inside the onboarding generator prompt, but do not state a hard byte/character truncation limit or `@file` import expansion syntax.
5. **Devin Cloud subdirectory `AGENTS.md` loading timing:** Devin CLI docs explicitly confirm lazy subdirectory discovery, whereas Devin Cloud's `onboard-devin/agents-md` page states only "in your project root (or anywhere else)" and the 16 KiB per-file injection cap without specifying eager vs. lazy loading for nested files.
6. **Factory's remediation guide (`factory.com/articles/fixing-the-repos-slowing-your-rollout`):** Returned only a bare HTML shell without body text when fetched directly, so only `factory.com/product/agent-readiness` and `factory.com/articles/measuring-agent-readiness` were cited.
