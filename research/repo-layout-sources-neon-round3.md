## 1. Full Readings of the Three Key arXiv Papers

### A. `arXiv:2602.11988v3` — *Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?*
- **URL:** `https://arxiv.org/html/2602.11988` (abstract: `https://arxiv.org/abs/2602.11988`)
- **Publisher / Authors / Date:** arXiv (`cs.SE`) — Thibaud Gloaguen, Niels Mündler-Sasahara, Mark Niklas Müller, Veselin Raychev, Martin Vechev (ETH Zurich & LogicStar.ai); v1 2026-02-12, **v3 2026-09-29**. **Label: measured.**
- **Exact setup:** Two Python benchmarks evaluated under single completions in Docker containers with git history and remotes stripped (web access allowed, <1% of calls, checked for no cheating):
  1. **SWE-bench Lite:** 300 tasks across 11 popular Python repos (none with developer-written context files). Conditions: `None` vs `LLM` (generated via each harness's recommended `/init` command/prompt on pre-patch state $R$).
  2. **CTXbench** (referred to as `Plan-Bench` in a Table 5 typo): 138 tasks (bug fixes and features) mined from 5,694 PRs across 12 recent/niche Python repos (≥400 PRs each) that already had developer-committed `AGENTS.md`/`CLAUDE.md` files (mean 641.0 words, range 24–2,003; mean 9.7 sections). Conditions: `None`, `LLM`, `Dev` (human-committed pre-patch file). Task descriptions and missing regression tests were generated by GPT-5.2 + Codex and manually reviewed (25/138 tests edited to remove over-specification; mean 75% patch coverage).
- **Models & agents:**
  - **Claude Code** with **Sonnet-4.5** (temp 0; Task tool enabled with Haiku-4.5 subagents)
  - **Codex** with **GPT-5.2** and **GPT-5.1 mini** (temp 0)
  - **Qwen Code** with **Qwen3-30b-coder** (vLLM, temp 0.7, top-p 0.8, 256K context, chat compression at 60%, shell output capped at 2,000 tokens)
  - Trace intent & overview judge: **GPT-OSS-120b**; category-ablation editor: **GPT-5.4**; AI-text detector: Pangram EditLens Llama-3.2 3B. (Exact CLI build numbers are not listed in the paper.)
- **Headline numbers (Tables 2, 3, 5, 6, 7, 8 & Section 4):**
  - **Resolution rates (Table 5):**
    - *SWE-bench Lite (None → LLM):* Sonnet-4.5 `59.9±3.0%` → `58.7±2.9%`; GPT-5.2 `56.6±2.9%` → `54.4±2.9%`; GPT-5.1 mini `47.7±3.1%` → `47.6±3.2%`; Qwen3-30B `31.1±2.7%` → `32.4±2.7%`. Average delta: **−0.5%** (CMH `p=0.87`, not significant).
    - *CTXbench (None → LLM → Dev):* Sonnet-4.5 `73.2%` → `65.2%` → `70.3%`; GPT-5.2 `65.2%` → `68.1%` → `68.1%`; GPT-5.1 mini `54.3%` → `50.7%` → `55.8%`; Qwen3-30B `45.7%` → `47.1%` → `53.6%`. Average delta: **LLM −2%** vs None (`p=0.37`); **Dev +2.4%** vs None (`p=0.21`); **Dev significantly beats LLM** (`p=0.038`; authors report ~7% relative margin in intro).
  - **Steps & cost (Tables 2 & 6, stratified permutation tests):**
    - *LLM vs None:* +2.45 steps (`p=0.0287`) and **+20% cost** (`p<0.00001`) on SWE-bench; +3.92 steps (`p=0.00004`) and **+23% cost** (`p=0.00064`) on CTXbench.
    - *Dev vs None (CTXbench):* +3.34 steps (`p=0.00002`) and **at most +19% cost** (`p=0.0126`).
  - **Instruction following & reasoning:** Mentioning `uv` raised calls from `<0.01` to `1.6`/instance; mentioning repo-specific tools raised calls from `<0.05` to `2.5`/instance. Adaptive reasoning tokens rose **+22% (GPT-5.2) / +10% (GPT-5.1 mini)** on SWE-bench with LLM files, and **+14% / +10%** (LLM) or **+20% / +2%** (Dev) on CTXbench.
  - **Overviews:** 100% of Sonnet-4.5, 99% of GPT-5.2, 95% of Qwen3-30B, 36% of GPT-5.1 mini LLM files, and 8/12 Dev files contained codebase overviews—yet overviews did **not** reduce steps-to-first-relevant-file.
- **What authors say works:** Omit LLM-generated context files (contrary to `/init` recommendations). Keep human-written files strictly to non-standard conventions and tooling not already in `README.md`, and evaluate before adopting.
- **Limits stated:** Python-only (heavy training-data familiarity may mask benefits for niche languages/toolchains); evaluates only test-pass resolution rate, not security or code efficiency.
- **What short summaries miss:**
  1. **Docs-removed ablation (Appendix B, Fig. 12):** When all `.md`, `docs/`, and example files were deleted from CTXbench repos (excluding Claude Code for cost), **LLM-generated context files improved resolution by +2.7% on average and beat Dev files.** Context files act as *redundant documentation* in well-documented repos, not universally harmful noise.
  2. **File length did not drive cost (Appendix B, Fig. 13):** Binning by context-file length showed no correlation with accuracy or per-instance cost. Cost rose because agents *obeyed* instructions (running more tests, linters, and searches)—confirmed in Table 7, where ablating the `testing` section significantly cut GPT-5.2 cost on both benchmarks (`p=0.023` CTXbench, `p=0.0035` SWE-bench) without hurting accuracy.
  3. **Duplicate-read quirk:** GPT-5.1 mini wasted extra steps searching for and re-reading `AGENTS.md` even though Codex had already injected it into context.
  4. **Stronger generator ≠ better file:** Generating files with GPT-5.2 or Sonnet-4.5 for weaker agents improved SWE-bench (+2%) but worsened CTXbench (−3%).

### B. `arXiv:2610.30571v1` — *Stale Instruction Files Override the Code in Coding Agents: A One-Sentence Fix*
- **URL:** `https://arxiv.org/html/2610.30571` (abstract: `https://arxiv.org/abs/2610.30571`)
- **Publisher / Authors / Date:** arXiv (`cs.SE`) — Xiaonan Xu (Georgia Tech), Wenjing Wu (CU Boulder); **2026-10-22**. **Label: measured.**
- **Exact setup:** 40 synthetic Python projects (3–8 working modules, passing test suite, instruction file, feature request not mentioning conventions). Each project required 4–5 convention choices drawn from 16 pairs (each pair tested in both directions across 11–12 projects, 5–6 per direction, eliminating model priors). In every project, existing code consistently used one convention while the project instruction file demanded the opposite. Each project ran twice per agent × condition = **320 valid runs** (non-interactive, 1,800s timeout, auto-memory and pip disabled, clean env vars). Blind conflict judge: **Claude Opus 5.5** (`--safe-mode --tools ""`).
- **Models & agent versions:**
  - **Claude Code `2.1.302`** with **Claude Sonnet 5.5** (`claude -p --model sonnet --permission-mode acceptEdits`)
  - **Codex CLI `0.163.0`** with **GPT-6 Sol** (`codex exec -s danger-full-access -m gpt-6-sol`)
- **Exact sentence tested (Section 4, verbatim):**
  > `When a repository’s documentation and its existing code disagree, follow the conventions used in the existing code, and in your final reply point out each inconsistency you found between the documentation and the code.`
- **Where it was placed:** In the **user-level instruction file**—`~/.claude/CLAUDE.md` (via `CLAUDE_CONFIG_DIR`) for Claude Code, and `~/.codex/AGENTS.md` (via `CODEX_HOME`) for Codex CLI. Notably, both tools inject the user-level file *first* in the same instruction user message as the project file, giving it instruction-level authority (unlike code, which arrives as lower-priority tool output under instruction hierarchy training).
- **Headline numbers (Section 5):**
  - **Without sentence:** **90.1%** of choices (649/720) followed the stale file; only **4.2%** followed the existing code (Claude Code: 86.4% stale / 7.5% code; Codex CLI: 93.9% stale / 0.8% code). Stale file won in **14 of 16** convention categories (Claude Code exceptions: Money and Configuration, <50%).
  - **Awareness without obedience:** Claude Code explicitly noted the conflict in **79 of 80** runs yet still followed the stale file in **86.2%** of choices in those runs. Codex CLI noted the conflict in only **2 of 80** runs.
  - **Destructive rewrites:** Without the sentence, Codex CLI rewrote existing working modules (≥20 lines deleted from pre-existing files) in **20 of 80** runs (median **198 lines removed across 9 files**, spanning 12/40 projects). Restoring original tests caused **17 of those 20** to fail. Claude Code rewrote existing code in 0 runs.
  - **With sentence:** Code-following jumped from **4.2% → 91.4%** (658/720; +87.2 pp, 95% CI 83.6–90.9): Claude Code `7.5% → 94.4%`, Codex CLI `0.8% → 88.3%`. Rewrites dropped to **0/80**. Overall test pass rate rose **89.4% → 100%** (Codex CLI `78.8% → 100%`). Both agents reported conflicts in **160/160** runs, with slightly fewer tool calls and less time.
- **What authors say works:** Put the precedence sentence in the user-level file today; agent makers should place it in the harness system prompt; model makers should train models to distinguish descriptive claims from behavioral rules.
- **Limits stated (Section 8):** Synthetic Python projects only; instruction file is always the outdated source (does not test the reverse case where the team intentionally wants to migrate away from legacy code conventions); single unattended feature runs; 2 agents/models.
- **What short summaries miss:**
  1. Claude Code's emphatic preamble (`"IMPORTANT: These instructions OVERRIDE any default behavior..."`) was **not** the cause—Codex CLI has no such preamble and followed the stale file even more often (93.9% vs 86.4%).
  2. Real-world drift examples documented in Figure 2: Supabase's skill file told agents to skip React 19 patterns for **13 days** after migrating to React 19; `openai/codex`'s `AGENTS.md` told agents for **24 days** to update a deleted document.

### C. `arXiv:2611.09802v1` — *When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents*
- **URL:** `https://arxiv.org/html/2611.09802` (abstract: `https://arxiv.org/abs/2611.09802`)
- **Publisher / Authors / Date:** arXiv (`cs.SE`) — Tural Mehtiyev, Biruk Tadesse, Lawrence Arkoh, Wesley Assunção (NC State University); **2026-11-06**. **Label: measured.**
- **Exact setup:** Three real-world stale path lines from active open-source repos, each surviving multiple later edits of its instruction file:
  1. **Command case (`pyflow`, Python):** `AGENTS.md` listed `pytest tests/ifds` after tests moved to `tests/analysis/ifds` (survived 2 later edits). 8 bugs (4 naming function, 4 broad) × 3 conditions × 5 repeats × 2 models = 240 runs.
  2. **Location case (`cog`, Python — deliberate contrast):** `AGENTS.md` named `python/cog/base_predictor.py` after it moved to `predictor.py` (survived 13 later edits). 6 nearby bugs (none needing that file) × 3 × 7 × 2 = 252 runs.
  3. **Procedure case (`aghub`, Rust):** `CLAUDE.md` placed new agents in `crates/core/src/agents/` after moving to `agents/src/agents/` (survived 4 later edits; another instruction file already had the new path). 8 bugs (4 naming function, 4 broad) × 3 × 5 × 2 = 240 runs.
  - **Total:** 22 tasks, **732 runs** across 3 conditions (`Stale`, `Corrected`, `Removed`), fresh isolated containers, git history stripped, 30-min cap, medium effort, bug report only.
- **Models & agent version:** **Claude Code `2.1.316`** (medium effort) with **Claude Haiku 5.5** and **Claude Sonnet 5.5**.
- **Headline numbers (Tables II & III):**
  - **Stale-path operations:**
    - *Command:* Stale **78/80** (Haiku 38/40, Sonnet 40/40) vs Corrected **0/80** vs Removed **1/80** (Holm-corrected `p=2e-28` Haiku, `p=2e-33` Sonnet).
    - *Procedure:* Stale **55/80** (Haiku 24/40, Sonnet 31/40) vs Corrected **0/80** vs Removed **20/80** (all 20 on broad reports where agents guessed `crates/core/src/agents/` from repo structure!).
    - *Location:* **0/84** across all conditions.
  - **Task success:** Virtually identical across all conditions (`p=1.0`; e.g., Sonnet 40/40 Command, 42/42 Location, 39–40/40 Procedure). In 4 Command tasks, all 15 Sonnet runs produced byte-for-byte identical patches.
  - **Tool calls & tokens:** Only 1 of 6 case×model cells showed a resolvable (exploratory) difference: **Sonnet on Command** rose from **5.8 → 7.8 tool calls** (+34%, median higher in 7/8 tasks; 152k → 195k tokens, n.s.). Critically, **Removed tied Stale at 7.8 calls (222k tokens)** because Sonnet had to rediscover how to run tests. Haiku's variance was too wide to resolve an effort delta.
  - **Silent false-green test checks:** In **64/80** stale Command runs, at least one test run executed **0 tests** yet Claude Code flagged **none** as errors because agents piped pytest through `tail`/`head` (masking pytest's non-zero exit code); Haiku also used `2>/dev/null` in 16/38 runs. In **19/40** Sonnet stale runs, the first verification of the fix ran zero tests.
  - **Recovery vs repayment (Table III, 133 stale-path encounters):** Operational recovery in **130/133** (98 via search, median 2 calls to recover). Final response disclosed the studied mismatch in only **21/133** (17/20 Sonnet Command runs with named functions, 0/20 broad; 3/38 Haiku Command; 1/24 Haiku Procedure; 0/31 Sonnet Procedure). **0/133 suggested repairing the file, and 0/732 edited any instruction file.**
- **What authors say works:** **Correct stale lines rather than deleting them** (deleting left agents guessing old paths in 20/80 Procedure runs and kept Sonnet's Command cost at 7.8 calls); audit high-frequency shared commands (especially test commands) first; run path-existence checkers; set `pipefail` in agent shells and treat "0 tests ran" as failure.
- **Limits stated (Section VI):** Only 3 repos/cases (instruction type confounded with repo/language); mostly small seeded defects; single vendor/harness (Claude Code); effort deltas are exploratory.
- **What short summaries miss:**
  1. **Deleting is strictly worse than correcting** for test commands and non-obvious layouts—an important nuance against "just delete stale lines."
  2. **Silent zero-test passes (`pytest ... | tail`)** are a major harness hazard uncovered by trajectory inspection.
  3. **Even when the prompt named the right module**, Sonnet still searched the stale Procedure folder in **12 of 20** runs, and agents cited the instruction file before acting in only **2 of 133** encounters.

## 2. Other 2025–2026 Empirical Studies (arXiv / SE Venues)

Every study below was opened directly on arXiv:

1. **Does the Agent's Map Match the Territory? Architectural Claims in AI Agent Context Files and Their Fit with the Code** — Bachan Ghimire, Daniela Damian (`2026-11-23`). `https://arxiv.org/abs/2611.29916` (**measured**)
   - *Setup:* Checked **41,090 path claims** and **184 dependency rules** across **3,602 context files in 3,346 OSS repos** against code & git history, plus 7,480 commits for new rule breaks.
   - *Numbers:* ~5% of path claims unresolvable, estimated **2.2% true errors** (comparable to READMEs at 3.5%); when code moves, **61%** of newly stale path claims are fixed (mostly in the same commit). By contrast, **33/184 (18%) of dependency rules were already broken the day they were written** (usually by legacy code) and stayed broken. Agent-assisted commits broke dependency rules 1.8× more often than human commits (0.29% vs 0.16%, 14 breaks total—not statistically significant).
2. **Do They Do as They Are Told? Investigating Coding Agents' Adherence to Explicit Instructions in Context Files** — Gianmario Voria, Yutaro Kashiwa, Gemma Catolino, Fabio Palomba (`2026-11-10`, TOSEM preprint). `https://arxiv.org/html/2611.13709` (**measured**)
   - *Setup:* 621 context-file snapshots across **268 repos** linked to **6,541 agent-generated commits** (25,822 changed files, 26 languages); 14,902 candidate instructions narrowed to 6,552 explicit/actionable/observable instructions and 2,053 evaluated via executable compliance scripts.
   - *Numbers:* Mean compliance **59.8%**, median **100.0%**—starkly bimodal: **54.4% (1,116)** followed in every applicable commit, **37.3% (766)** followed in *none*, only **8.3% (171)** partial. Significant compliance gaps exist across agents (including Copilot vs Claude Code) and instruction types, motivating mechanical enforcement for rules that fall in the 0% tail.
3. **Do Coding Agents Follow AGENTS.md? The Effect of Policy Wording on Instruction Compliance** — Rikuto Tsuchida, Youmei Fan, Kazumasa Shimari, Raula Gaikovina Kula, Kenichi Matsumoto (`2026-11-03`, submitted to IEICE). `https://arxiv.org/html/2611.04367` (**measured**)
   - *Setup:* Inserted one policy phrased in 4 styles (including Conditional, Prescriptive, Explanatory) into ACFs across **86 CTXbench tasks** × **4 harness–model combinations**.
   - *Numbers:* In 3 of 4 harness–model pairs where wording significantly affected compliance, **Conditional phrasing ("if X, do Y") had lower compliance than Prescriptive and Explanatory phrasing**. Which of Prescriptive vs Explanatory won varied by harness–model pair (largest swings on weaker models).
4. **Toward an Evidence-Based Template for Agent Instruction Files: An Empirical Study of Adoption, Consistency, and Maintenance** — Mehedi Hasan Shanto, Md. Anaytul Islam, Muhammad Asaduzzaman, Alioune Ngom (`2026-11-02`, v2 `2026-11-07`). `https://arxiv.org/abs/2611.02383` (**measured**)
   - *Setup:* **3,387 instruction files** across **1,000 GitHub repos** spanning 4 formats (`AGENTS.md`, `CLAUDE.md`, Copilot instructions, Cursor rules), plus manual audit of 386 paired sections and generation benchmark (`AGIT-Instruct`).
   - *Numbers:* **42.2%** of higher-popularity repos maintain multiple formats; **16.1%** of 386 paired sections give **divergent guidance**; **40.4%** of files have only 1 recorded modification ever. Template-guided generation raised structural category coverage from **18.7% → 82.8%** (manual check of 278 generated categories: 19.4% full / 61.2% partial preservation of developer intent).
5. **What Open-Source Projects Tell Their Coding Agents: A Census of AGENTS.md and CLAUDE.md** — Pawel Zarzycki (`2026-10-22`, v2 `2026-10-26`). `https://arxiv.org/abs/2610.31715` (**measured**)
   - *Setup:* Census of **22,854 active GitHub repos** across 13 languages; **341,852 statements** annotated.
   - *Numbers:* Root agent instructions appear in **26.3%** of repos and **59.6%** of the most-starred repos; when both exist, `CLAUDE.md` usually points to `AGENTS.md`. **74.0%** of directives give **no rationale**. One-third show generator signatures/shared text; 4 in 5 are edited after creation.
6. **Lessons Outlive Their Failures: A Case Study of Rules for AI Coding Agents** — Hassan Hassanzadeh Aliabadi (`2026-10-23`). `https://arxiv.org/abs/2610.32578` (**measured**, exploratory single-repo)
   - *Setup:* 6-week case study of 1 repo edited daily by 3 agent tools; ledger of **118 agent failures**, LLM drift audit against 47 known stale statements + 20 planted errors, and replay of 5 past failures with/without their fixes.
   - *Numbers:* Drift was the #1 failure class (**48/118**). Monthly LLM audit caught **~50%** of known drift on Sonnet 5.5 (≥93% precision). On Sonnet 5.5, **3 of 4** completed replayed tasks no longer failed even *without* their written rule—only a stale-count failure recurred without its mechanical check, and the check stopped it in 100% of runs. Conclusion: retire obsolete prose rules; keep mechanical checks for drift.
7. **The Role of Agentic Instruction Categories for Code Generation: A Study of Five Python Libraries** — Warren Gerald Polandra, Yoshiki Higo, Raula Gaikovina Kula (`2026-10-15`). `https://arxiv.org/html/2610.21421` (**measured**)
   - *Setup:* All 31 non-empty combinations of 5 categories (`Repository Overview`, `Function Description`, `Implementation Detail`, `Testing`, `Reconstruction Steps`) × 5 Python libraries × 2 LLMs (Gemma 4, GPT-5.4) = 310 generated variants.
   - *Numbers:* Instruction count alone did not predict token usage. 0% of Gemma 4 variants and **12.99%** of GPT-5.4 variants passed all tests; `Reconstruction Steps` gave GPT-5.4's highest full-pass rate and closest structural match to human code.
8. **Compact Documentation for Coding Agents: A Benchmark, an Optimizer, and Why It Does Not Transfer** — Md Shohel Arman, Igor Molybog (`2026-09-25`). `https://arxiv.org/html/2609.31587` (**measured**)
   - *Setup:* Roundtrip code-regeneration benchmark (11 SWE-bench Verified fixtures, `gemini-3.5-flash`) plus end-to-end issue resolution across 2 model families and 10 repos.
   - *Numbers:* **Completeness, not length, drives fidelity:** a 38-word description and a 664-word description carrying the same 5 facts gave identical uplift (confirmed even with 28 confusable config keys in long filler). Yet **when source code is present, neither static compact documentation nor retrieved context beat the issue alone** (longer docs made resolution slightly worse).
9. **From Agent Behaviour to Agent-Friendly Documentation** — Zhijun Gao, Jing Chen (`2026-08-20`). `https://arxiv.org/abs/2608.20195` (**measured**)
   - *Setup:* 557 SWE-chat sessions (94,813 events, 3,033 doc interactions) + 33,097 AIDev agent PRs (690,260 file changes).
   - *Numbers:* **60.5%** of doc interactions are with agent-facing files (instructions/working notes) vs **10.6%** classical tech docs and **1.3%** API references. Consultation is **70.2% self-initiated** vs 7.5% failure-driven, associated with *less* immediate testing (lift 0.23; adjusted OR 0.39), and **code is touched before docs 4.7× more often** in multi-commit PRs.
10. **Context Rot in AI-Assisted Software Development** — Christoph Treude, Sebastian Baltes (`2026-06-08`). `https://arxiv.org/html/2606.09090` (**measured**)
    - *Setup:* Applied README checker `DOCER` to **612 AI config files across 356 randomly sampled repos** (29,454 candidate elements; 18,048 verified at first commit).
    - *Numbers:* **23.0% of repositories (82/356, 95% CI 18.8–27.2%)** had ≥1 stale code-element reference (**230/18,048 = 1.27%** of verified references had gone stale).
11. **On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents** — Jai Lal Lulla et al. (`2026-01-23`, v2 `2026-03-30`, ICSE JAWs 2026). `https://arxiv.org/html/2601.20404` (**measured**)
    - *Setup:* **10 repos, 124 PRs**, executed with vs without `AGENTS.md`.
    - *Numbers:* Median wall-clock time fell **−28.64%** (98.57s → 70.34s; mean −20.27%, Wilcoxon `p<0.05`); median output tokens fell **−16.58%** (2,925 → 2,440; mean −20.08%, `p<0.05`); median total tokens were flat (−1.29%, n.s.).
12. **Agent READMEs: An Empirical Study of Context Files for Agentic Coding** — Worawalan Chatlatanagulchai et al. (`2025-11-17`, v2 `2026-08-09`). `https://arxiv.org/abs/2511.12884` (**measured**)
    - *Setup:* **2,303 context files across 1,925 repos**.
    - *Numbers:* Heavy focus on functional specs—testing (**75.9%**), implementation (**70.8%**), architecture (**68.1%**) — vs a "guardrail gap" in security (**14.8%**) and performance (**14.5%**).
13. **Metrics-in-the-Loop: Complexity Feedback Reshapes Agent-Written Code** — Nicolas Chapados, Jean-François Gagné, Nouha Dziri (`2026-11-18`). `https://arxiv.org/html/2611.23817` (**measured**)
    - *Setup:* Injected cheap per-turn cyclomatic complexity and test-coverage-gap messages during long autonomous runs on Commit0, SlopCodeBench, and SWE-EVO across 4 models.
    - *Numbers:* Complexity feedback cut structural erosion ($E_{10}$) by **7.8–24.6 percentage points** across all 4 models on Commit0 and SlopCodeBench (keeping SlopCodeBench erosion ≤0.022).

**What searches found NOTHING controlled for (stated plainly):** Searches across arXiv and ACL Anthology for 2025–2026 studies found **no controlled empirical measurements** comparing **feature folders vs layer folders**, **colocated tests vs separate test trees**, **source-file maximum length thresholds**, **duplicate filenames across directories**, or **per-folder READMEs** on coding-agent success or token cost. (Discussions of feature folders and colocated tests remain engineering opinion.)

## 4. Mobile and Desktop App Repositories with Agents

### a. Xcode Projects (`project.pbxproj` vs Buildable Folders, Swift Packages, Tuist, XcodeGen)
- **Why `.xcodeproj/project.pbxproj` hurts agents:** Traditional Xcode projects enumerate every file reference and build phase entry inside a monolithic `project.pbxproj` with implicit configurations, causing frequent diffs and merge conflicts whenever files are added, moved, or deleted (**documented**: Tuist Projects guide `https://tuist.dev/en/docs/guides/features/projects`, Apple Xcode 16 Release Notes `https://developer.apple.com/tutorials/data/documentation/xcode-release-notes/xcode-16-release-notes.json`).
- **Xcode 16+ Buildable Folders (folder-synchronized groups):**
  - Introduced in **Xcode 16** (`https://developer.apple.com/tutorials/data/documentation/xcode-release-notes/xcode-16-release-notes.json`, Apple, **documented**): *"Buildable folders only record the folder path into the project file without enumerating the contained files. This minimizes diffs to the project when files are added and removed, and avoids source control conflicts with your team."*
  - **How to convert:** Right-click an existing group in Xcode's Project Navigator → **"Convert to Folder"**. In Xcode 16+, "New Group" and "New Group from Selection" default to folder-backed groups; to keep a legacy opaque resource folder, uncheck **"Build Folder Contents"** in the File Inspector.
  - Because the folder is filesystem-synchronized, an agent can add, rename, or delete `.swift` files on disk without editing `project.pbxproj`.
- **Tuist:** Defines projects declaratively in `Project.swift` / `Workspace.swift` (similar to SwiftPM) and generates `.xcodeproj` on demand (`tuist generate`, `tuist build`, `tuist test`), eliminating checked-in `project.pbxproj` conflicts and enforcing explicit module boundaries (`https://tuist.dev/en/docs/guides/features/projects`, **documented**).
- **XcodeGen:** Generates `.xcodeproj` from a YAML/JSON `project.yml` spec and disk directories so `.xcodeproj` can be removed from git (`https://raw.githubusercontent.com/yonaskolb/XcodeGen/master/README.md`, **documented**). XcodeGen's `ProjectSpec.md` also supports `syncedFolder` to emit Xcode 16's synchronized/buildable folders directly (`https://raw.githubusercontent.com/yonaskolb/XcodeGen/master/Docs/ProjectSpec.md`, **documented**).
- **Swift Packages:** Pure `Package.swift` modules require no `.xcodeproj` at all (file discovery is directory-based by default) and pair cleanly with a thin Xcode app shell.

### b. Building, Testing, and Official Agent Tools in Xcode
- **CLI testing (`xcodebuild`):** Apple's *Running tests and interpreting results* (`https://developer.apple.com/tutorials/data/documentation/xcode/running-tests-and-interpreting-results.json`, **documented**) documents running scheme test plans via `xcodebuild test -scheme <Scheme>` and selecting subsets via test plans for fast unit feedback during edits. *(Note: exact `-only-testing:` / `-destination` and `swift test --filter` CLI flag pages were not directly opened from primary Apple/SwiftPM docs—see Section 5.)*
- **Apple's official Coding Intelligence & MCP server (`xcrun mcpbridge`):**
  - *Coding intelligence* (`https://developer.apple.com/tutorials/data/documentation/xcode/coding-intelligence.json`, Apple, 2026, **documented**): Xcode has built-in agentic coding support (with Claude Agent, Codex, Gemini, and other providers configurable in Xcode → Settings → Intelligence, and parallel agent panes).
  - *Giving external agents access to Xcode* (`https://developer.apple.com/tutorials/data/documentation/xcode/giving-external-agents-access-to-xcode.json`, Apple, 2026, **documented**): External CLI agents connect to a running Xcode instance via Apple's built-in MCP bridge (`xcrun mcpbridge`). Enable under **Xcode → Settings → Intelligence → Model Context Protocol → Allow External Agents to Use Xcode Tools** (`Always` or `While Xcode is Open`), open the project in Xcode, and register:
    - Claude Code: `claude mcp add --transport stdio xcode -- xcrun mcpbridge`
    - Codex: `codex mcp add xcode -- xcrun mcpbridge`
  - *Extending and customizing agents* (`https://developer.apple.com/tutorials/data/documentation/xcode/extending-and-customizing-agents.json`, Apple, 2026, **documented**): Xcode exposes built-in skills (e.g., plan mode, localization), per-agent allowed commands/tools in Intelligence settings, and product-specific agent config folders for Xcode-hosted agents.

## 6. Enforcement: Hooks, Deny Rules, and `REVIEW.md`

### A. Working Examples (Claude Code — `https://code.claude.com/docs/en/hooks-guide.md`, `https://code.claude.com/docs/en/hooks.md`, `https://code.claude.com/docs/en/permissions.md`, **documented**)

1. **Protect paths (PreToolUse hook + Edit/Read deny rules):**
   - Hook script `.claude/hooks/protect-files.sh` (exit `2` + stderr message blocks `Edit|Write`):
     ```bash
     #!/bin/bash
     INPUT=$(cat)
     FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
     FILE_PATH="${FILE_PATH//\\//}"
     for pattern in ".env" "package-lock.json" ".git/"; do
       if [[ "$FILE_PATH" == *"$pattern"* ]]; then
         echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2
         exit 2
       fi
     done
     exit 0
     ```
   - Registered in `.claude/settings.json` under `hooks.PreToolUse` with `"matcher": "Edit|Write"` and `"command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh"`.
   - Paired with `permissions.deny` (e.g., `Edit(/.env)`, `Read(./.env)`) because **deny rules from any scope always beat allow rules** and also block `@`-file mentions.
2. **Block a command (PreToolUse JSON decision or Codex `.rules`):**
   - Claude Code `PreToolUse` (`"matcher": "Bash"`) exits `0` and prints:
     ```json
     {
       "hookSpecificOutput": {
         "hookEventName": "PreToolUse",
         "permissionDecision": "deny",
         "permissionDecisionReason": "Use pnpm test <file> instead of running the full suite."
       }
     }
     ```
   - OpenAI Codex (`https://learn.chatgpt.com/docs/agent-configuration/rules.md`, **documented**): Starlark `prefix_rule(pattern=["gh","pr","view"], decision="prompt", justification="...", match=[...], not_match=[...])` in `<repo>/.codex/rules/*.rules` (loaded when `.codex/` is trusted) or `~/.codex/rules/default.rules`.
3. **Run a check/formatter after an edit (PostToolUse):**
   - `.claude/settings.json`:
     ```json
     {
       "hooks": {
         "PostToolUse": [
           {
             "matcher": "Edit|Write",
             "hooks": [{ "type": "command", "command": "f=$(jq -r '.tool_input.file_path') && npx prettier --write --ignore-unknown \"$f\"" }]
           }
         ]
       }
     }
     ```
   - Other harnesses with native hooks: **Cursor** `.cursor/hooks.json` (`preToolUse`, `postToolUse`, `beforeShellExecution`, `afterFileEdit`, `beforeReadFile`, runs in cloud agents too, and can load third-party Claude Code hooks — `https://cursor.com/docs/hooks.md`, **documented**); **Gemini CLI** synchronous lifecycle hooks (`BeforeAgent`, `AfterAgent`, `BeforeModel`, `AfterModel`, etc. — `https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/hooks/index.md`, **documented**).

### B. What a Claude Code Hook Can Return & Documented Limits (`https://code.claude.com/docs/en/hooks.md`, **documented**)
- **Return channels:**
  - **Exit `0`:** success; valid JSON on stdout is parsed. Universal fields: `continue` (`false` stops Claude after the hook, though on `PreToolUse` you must *also* return `permissionDecision: "deny"`), `stopReason`, `systemMessage`, `terminalSequence`.
  - **Exit `2`:** blocking error on blockable events; stderr is sent back to Claude as the reason. (Mixing exit `2` with JSON keeps a `PreToolUse` call blocked even if JSON says `"allow"`.)
  - **Other non-zero exit:** non-blocking error unless `onFailure: "block"` (or `WorktreeCreate`/`WorktreeRemove`, where any non-zero fails).
  - **`PreToolUse` `hookSpecificOutput`:** `permissionDecision` (`"allow"` | `"deny"` | `"ask"` | `"defer"`), `permissionDecisionReason`, `updatedInput` (replaces entire tool input before execution).
  - **`PostToolUse` `hookSpecificOutput` / top-level:** `decision: "block"` + `reason` (appended to tool result), `additionalContext`, `classifierContext` (for auto-mode classifier, v2.1.236+), `updatedToolOutput` (replaces what Claude sees—not what already happened on disk).
- **Documented limits & pitfalls:**
  1. **10,000-character hard cap** per field (`additionalContext`, `systemMessage`, `initialUserMessage`, plain stdout)—excess is spilled to a session file with a 2,000-char preview, **no setting to raise it**, and Claude is not told to read the spilled file.
  2. **Bash bypass:** An `Edit|Write` hook does **not** catch a `Bash` command modifying the same file; use `FileChanged` to react to on-disk writes (cannot block), or OS sandboxing to restrict shell writes.
  3. **`@`-mention bypass:** `PreToolUse` does not fire when a user `@`-mentions a file unless `Read` deny rules are set or `CLAUDE_CODE_DISABLE_FILE_MENTIONS=1` (v2.1.299+, ignored in project/local settings).
  4. **Stop-hook cap:** Claude Code overrides a `Stop` hook after **8 consecutive blocks** with no tool call in between (check `stop_hook_active` or raise `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`).
  5. **Headless `-p` trust trap:** Interactive sessions hold back repo hooks until workspace trust is accepted, **but `claude -p` and SDK sessions treat the folder as trusted and execute committed `.claude/settings.json` hooks immediately** (use `--bare` or `--settings '{"disableAllHooks": true}'` on untrusted repos).
  6. **10-second interrupt cutoff:** `PostToolUse` hooks killed after 10s if interrupted with `Ctrl+Enter` (or immediately on `Esc`).

### C. `REVIEW.md` and Other Review-Rules Files
- **Claude Code Review — `REVIEW.md`** (`https://code.claude.com/docs/en/code-review-customize.md`, **documented**):
  - **What / where:** Freeform Markdown at repo root (`REVIEW.md`) plus optional subdirectory `REVIEW.md` files (on protected branches), read *only* by Anthropic's managed GitHub Code Review service (not local interactive sessions; separate from `CLAUDE.md` to avoid bloating coding sessions).
  - **Security model:** Always read from the **protected default branch** or **ruleset-protected base branch**, **never** from the PR's own head branch—so a PR cannot weaken its own review rules. Severity downgrades, path/issue exclusions, and nit caps are honored *only* from the root `REVIEW.md` (or files beside it) on a protected branch, **never** from an included `SKILL.md`.
  - **What a good one contains:** Severity recalibration, explicit skip lists (generated code, lockfiles), domain invariants/checks (e.g., migrations, tests for new endpoints), and plain-English rules (if including a `SKILL.md`, note Code Review strips `!` commands, doesn't expand `$ARGUMENTS` or `@file` links, and mangles certain punctuation like `[ ]`, `< >`, `|`, `@`).
- **Other tools' review rules:**
  - **GitHub Copilot** (`https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions`, **documented**): Uses `.github/copilot-instructions.md`, path-scoped `.github/instructions/*.instructions.md` (with `applyTo` and `excludeAgent: "code-review"` / `"coding-agent"` to split coding vs review guidance), plus root/nested `AGENTS.md` (or root `CLAUDE.md`/`GEMINI.md`).
  - **Cursor Bugbot** (`https://cursor.com/docs/bugbot.md`, **documented**): Reads PR comments as context, automatically excludes files marked `linguist-generated` in `.gitattributes` (so they don't count against Bugbot's PR-size skip limit), skips credential-like paths (`.env`, `*.pem`, `*.tfvars`), and supports verbose rule debugging via `bugbot run verbose=true`.

# Top 10 Additions or Corrections for the Repository Layout Standard (Ranked by Impact)

1. **Correct stale paths/commands—don't just delete them—and add a CI path-existence check on `AGENTS.md`.** Stale test commands waste ~34% more tool calls for Sonnet and trigger silent 0-test runs (19/40 runs); deleting the line leaves agents guessing old folders (20/80 runs) and paying the same 7.8-call cost as stale (`arXiv:2611.09802`, `https://arxiv.org/html/2611.09802`; `arXiv:2606.09090`, `https://arxiv.org/html/2606.09090`).
2. **Enforce invariants mechanically (linters, dependency checks, `PreToolUse`/`PostToolUse` hooks, CI gates) rather than relying on prose rules.** 37.3% of observable prose rules are ignored 100% of the time (`arXiv:2611.13709`, `https://arxiv.org/html/2611.13709`), 18% of prose dependency rules are broken on day 1 (`arXiv:2611.29916`, `https://arxiv.org/abs/2611.29916`), and per-turn automated metric feedback cuts code erosion 7.8–24.6 pp (`arXiv:2611.23817`, `https://arxiv.org/html/2611.23817`).
3. **Update the `CLAUDE.md` `@AGENTS.md` guidance for Claude Code v2.1.277+ (and warn about `CLAUDE.local.md` shadowing).** Claude Code now reads `AGENTS.md` natively when no `CLAUDE.md` or `CLAUDE.local.md` exists; keeping a 1-line `CLAUDE.md` (`@AGENTS.md`) is now for backward compatibility (<v2.1.277) and preventing `CLAUDE.local.md` from silencing `AGENTS.md` (`https://code.claude.com/docs/en/memory.md`; `https://code.claude.com/docs/en/changelog.md`). Never maintain two parallel rule files—16.1% diverge (`arXiv:2611.02383v2`, `https://arxiv.org/abs/2611.02383`).
4. **Standardize parallel worktree support in every repo (`.worktreeinclude`, `.cursor/worktrees.json`, `t3.json` setup + marker files, dynamic ports/DBs, and content-addressed package managers instead of symlinked `node_modules`).** Avoids checkout collisions, install races, and main-checkout corruption across Claude Code, Codex, Cursor, and T3 Code (`https://code.claude.com/docs/en/worktrees.md`, `https://cursor.com/docs/configuration/worktrees.md`, `https://learn.chatgpt.com/docs/environments/git-worktrees.md`, `https://raw.githubusercontent.com/pingdotgg/t3code/main/scripts/setup-worktree.ts`). Note also Git's warning against worktrees in submodule superprojects (`https://git-scm.com/docs/git-worktree`).
5. **Add a dedicated Apple/Mobile section: convert Xcode groups to Xcode 16+ buildable folders (or use SwiftPM / Tuist / XcodeGen), enable `xcrun mcpbridge`, and follow Expo's `src/app/` + CNG rules.** Eliminates `project.pbxproj` merge/corruption failures and gives agents native build/test access (`https://developer.apple.com/tutorials/data/documentation/xcode-release-notes/xcode-16-release-notes.json`, `https://developer.apple.com/tutorials/data/documentation/xcode/giving-external-agents-access-to-xcode.json`, `https://raw.githubusercontent.com/expo/expo/main/packages/create-expo/template/agent-files/AGENTS.md`).
6. **Separate PR review rules (`REVIEW.md` on a protected default branch, `.gitattributes` `linguist-generated`, Copilot `excludeAgent`) from interactive coding rules (`AGENTS.md`).** Prevents review noise from bloating every coding session and stops PRs from weakening their own review gates (`https://code.claude.com/docs/en/code-review-customize.md`, `https://cursor.com/docs/bugbot.md`, `https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions`).
7. **Require `pipefail` / non-zero exit on zero-tests-collected in test scripts and include an exact single-test command (plus "do not run full suite") in `AGENTS.md`.** Prevents silent false-green checks when agents pipe output through `tail`/`head` (`arXiv:2611.09802`, `https://arxiv.org/html/2611.09802`) and mirrors practice in `t3code`, `sentry`, `next.js`, `bun`, `workers-sdk`, `react-native`.
8. **Write rules in prescriptive or explanatory phrasing—avoid conditional ("if X, do Y") phrasing—and include a brief rationale.** Conditional wording had lower compliance in 3 of 4 harness–model pairs (`arXiv:2611.04367`, `https://arxiv.org/html/2611.04367`), and 74% of OSS rules omit rationale (`arXiv:2610.31715v2`, `https://arxiv.org/abs/2610.31715`).
9. **Refine the `arXiv:2602.11988` summary and add a "restructure safely" Git rule (separate pure moves from edits; batch below `diff.renameLimit=1000` / `merge.renameLimit=7000`).** Clarify that `2602.11988v3` showed developer files beat LLM files (`p=0.038`), LLM files *helped* (+2.7%) when docs were absent, and cost came from obeyed test/check instructions rather than file length (`https://arxiv.org/html/2602.11988`). For moves, pair language-aware tools with pure-move commits so Git's 50% similarity detector and rename limits don't break history (`https://git-scm.com/docs/git-config`, `https://git-scm.com/docs/git-diff`).
10. **Warn about hook & permission boundaries (`CLAUDE_CODE_DISABLE_FILE_MENTIONS=1`, `Read`/`Edit` deny vs Bash bypass, 10,000-char hook output cap, and `-p` auto-trusting repo hooks).** Prevents false confidence in `Edit|Write` hooks and ensures CI/headless runs don't blindly execute untrusted repo hooks (`https://code.claude.com/docs/en/hooks.md`, `https://code.claude.com/docs/en/permissions.md`).
