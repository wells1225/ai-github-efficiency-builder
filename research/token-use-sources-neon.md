## 1. Findings (A–G)

### A. Fixed context per thread

- **What loads before the first prompt:** Before you type anything, Claude Code loads the system prompt, upfront tool definitions, environment/git info, `CLAUDE.md` (or `AGENTS.md`) hierarchy and unscoped rules, the first 200 lines or 25 KB of auto memory (`MEMORY.md`), MCP tool names and server instructions, skill descriptions, custom subagent descriptions, and any `SessionStart` hook output. Inspect live allocation with `/context` (or `/context all`), `/doctor` (unused plugins/MCPs/skills and skill-listing cost), `/skill-doctor` (per-skill context cost and invocation counts), and `/usage` (attribution by skill, subagent, plugin, and MCP server). — **Commands:** `/context`, `/doctor`, `/skill-doctor`, `/usage` — [context-window](https://code.claude.com/docs/en/context-window), [commands](https://code.claude.com/docs/en/commands), [skills](https://code.claude.com/docs/en/skills), [plugins/measure](https://code.claude.com/docs/en/plugins/measure), [memory](https://code.claude.com/docs/en/memory) — **documented**
- **Disabling plugins per user or per project (and synced claude.ai plugins):** Set `"<name>@<marketplace>": false` under `enabledPlugins` in `~/.claude/settings.json` (user), `.claude/settings.json` (project), or `.claude/settings.local.json` (local), or run `claude plugin disable <id>`. To stop claude.ai-synced plugins from loading or downloading entirely, set `syncClaudeAiPlugins: false` (or `"<name>@synced": false` for one). — **Settings / CLI:** `enabledPlugins`, `syncClaudeAiPlugins`, `claude plugin disable` — [plugins/loading](https://code.claude.com/docs/en/plugins/loading), [settings-reference](https://code.claude.com/docs/en/settings-reference) — **documented**
- **Controlling skill listing size and hiding skills:** Every enabled skill's name and description enters context every turn under a default character budget of 1% of the context window (`skillListingBudgetFraction`, default `0.01`; fallback 8,000 chars) and 1,536 chars per entry (`skillListingMaxDescChars`, default `1536`). Shrink it by setting `SLASH_COMMAND_TOOL_CHAR_BUDGET`, lowering `skillListingBudgetFraction` / `skillListingMaxDescChars`, adding `disable-model-invocation: true` in `SKILL.md` frontmatter (removes description from model context while keeping `/name` manual invocation), using `skillOverrides` (`"name-only"`, `"user-invocable-only"`, or `"off"`), disabling claude.ai synced skills (`syncClaudeAiSkills: false`), disabling bundled skills (`CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`), or disabling all skills for a session (`--disable-slash-commands`). — **Settings / Env / Flags:** `skillListingBudgetFraction`, `skillListingMaxDescChars`, `SLASH_COMMAND_TOOL_CHAR_BUDGET`, `skillOverrides`, `disable-model-invocation: true`, `syncClaudeAiSkills`, `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS`, `--disable-slash-commands` — [skills](https://code.claude.com/docs/en/skills), [settings-reference](https://code.claude.com/docs/en/settings-reference), [env-vars](https://code.claude.com/docs/en/env-vars), [cli-reference](https://code.claude.com/docs/en/cli-reference) — **documented**
- **MCP tool search, deferred tools, and server instructions:** On supported models (Opus 4 / Sonnet 4 / Haiku 4.5 and later on Anthropic API), MCP tool search is **on by default** when `ENABLE_TOOL_SEARCH` is unset or `true`, deferring schemas so only tool names and server instructions (each capped at 4,096 chars by default, tunable via `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`) load upfront; `auto` / `auto:N` loads upfront until deferrable tools hit 10% / `N`% of context, and `"alwaysLoad": false` on a server forces deferral even for author-marked upfront tools. Tool search is shown to preserve ~85% of tool-definition tokens in Anthropic's 50+-tool test (`~77K` → `~8.7K`). — **Env / Config:** `ENABLE_TOOL_SEARCH`, `alwaysLoad`, `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`, `MAX_MCP_OUTPUT_TOKENS` (default `25000`) — [mcp](https://code.claude.com/docs/en/mcp), [env-vars](https://code.claude.com/docs/en/env-vars), [advanced-tool-use](https://www.anthropic.com/research/advanced-tool-use) — **documented** (85% reduction: **measured**)
- **Disabling individual MCP servers and claude.ai connectors:** Disable servers per project via `/mcp` (writes `disabledMcpServers` in project config), reject `.mcp.json` servers via `disabledMcpjsonServers`, block any server globally via `deniedMcpServers` / `allowedMcpServers`, or ignore all configured servers with `--strict-mcp-config`. Turn off synced claude.ai connectors with `disableClaudeAiConnectors: true` (any settings file; any-source-true semantics) or `ENABLE_CLAUDEAI_MCP_SERVERS=false`, or block one connector in `deniedMcpServers` (e.g., `{"serverName": "claude.ai Slack"}`). — **Settings / Env / Flags:** `disabledMcpServers`, `disabledMcpjsonServers`, `deniedMcpServers`, `allowedMcpServers`, `disableClaudeAiConnectors`, `ENABLE_CLAUDEAI_MCP_SERVERS`, `--strict-mcp-config` — [mcp](https://code.claude.com/docs/en/mcp), [settings-reference](https://code.claude.com/docs/en/settings-reference), [env-vars](https://code.claude.com/docs/en/env-vars), [cli-reference](https://code.claude.com/docs/en/cli-reference) — **documented**
- **Disabling built-in tools, git instructions, hooks, and minimal mode:** Restrict built-in tools with `--tools` (`""`, `"default"`, or `"Bash,Edit,Read"`), or remove specific tools from context with `--disallowedTools` / `permissions.deny` using bare tool names (`"WebFetch"`, `"mcp__*"`). Drop built-in git workflow instructions and startup git-status snapshots with `includeGitInstructions: false` (`CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`), disable hooks with `disableAllHooks: true`, or skip all auto-discovered hooks/skills/plugins/MCP/memory/`CLAUDE.md` in scripted API runs with `--bare` / `CLAUDE_CODE_SIMPLE=1` (note: `--bare` does not use claude.ai OAuth). — **Flags / Settings / Env:** `--tools`, `--disallowedTools`, `permissions.deny`, `includeGitInstructions`, `disableAllHooks`, `--bare`, `CLAUDE_CODE_SIMPLE` — [cli-reference](https://code.claude.com/docs/en/cli-reference), [settings-reference](https://code.claude.com/docs/en/settings-reference), [env-vars](https://code.claude.com/docs/en/env-vars) — **documented**
- **`CLAUDE.md`, auto memory, and subagent description limits:** Official guidance is to keep `CLAUDE.md` **under 200 lines** ("Files over 200 lines consume more context and may reduce adherence"), move specialized workflows into skills or `.claude/rules/*.md` with `paths:` frontmatter (loaded on demand), exclude irrelevant repo files via `claudeMdExcludes`, or disable auto memory (`autoMemoryEnabled: false` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`) or all `CLAUDE.md` (`CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`). Custom subagent `description` fields load at startup (warning fires above 15,000 combined tokens); move details into each agent's body prompt. — **Settings / Env:** `claudeMdExcludes`, `autoMemoryEnabled`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS` — [memory](https://code.claude.com/docs/en/memory), [costs](https://code.claude.com/docs/en/costs), [sub-agents](https://code.claude.com/docs/en/sub-agents) — **documented**
- **What native subagents vs. delegated SDK child agents inherit:** A native non-fork subagent starts fresh with its own system prompt (not the full Claude Code system prompt), skips auto memory and output style, and by default loads the `CLAUDE.md` hierarchy and git snapshot—except built-in `Explore` and `Plan` (which skip both) and custom subagents setting `omitClaudeMd: true`. By contrast, a separate top-level Agent SDK session (such as a T3 Code delegated child thread) loads whatever `systemPrompt`, `settingSources`, `tools`, `plugins`, and `mcpServers` the host app passes—defaulting to all filesystem `["user", "project", "local"]` settings plus `~/.claude.json`, auto memory, and claude.ai connectors unless explicitly suppressed. — **Options:** `omitClaudeMd: true` (subagent frontmatter); SDK `Options`: `systemPrompt` (default minimal unless `{type:"preset", preset:"claude_code"}`), `settingSources` (default `["user","project","local"]`; `[]` disables them), `tools`, `allowedTools` (pre-approves only, does not restrict), `disallowedTools` (bare names remove from context), `plugins` (supports `skipMcpDiscovery`), `mcpServers`, `strictMcpConfig`, `env`, `settings` — [sub-agents](https://code.claude.com/docs/en/sub-agents), [agent-sdk/configuration](https://code.claude.com/docs/en/agent-sdk/configuration), [agent-sdk/modifying-system-prompts](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts), [agent-sdk/claude-code-features](https://code.claude.com/docs/en/agent-sdk/claude-code-features), [agent-sdk/typescript](https://code.claude.com/docs/en/agent-sdk/typescript) — **documented**

### B. Context growth

- **Auto-compact triggers and controls:** On native 1M-window models (Fable models, Opus 4.7+, Sonnet 5+, Haiku 5.5), auto-compaction triggers at **~967K tokens** by default; on 200K models (or when `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`), it compacts at the **200K boundary**. Control it via `autoCompactWindow` (or per-model in `modelSettings`, min `100000`), `/autocompact <size|auto>`, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (highest precedence; accepts `200k`/`1M` on v2.1.304+), `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (1–100% of auto-compact window; can only lower the threshold, applies to main + subagents), `autoCompactEnabled: false` / `DISABLE_AUTO_COMPACT=1`, `DISABLE_COMPACT=1`, or per-subagent `autoCompactWindow` frontmatter (v2.1.296+). — **Settings / Env / Commands:** `autoCompactWindow`, `modelSettings.<m>.autoCompactWindow`, `autoCompactEnabled`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`, `DISABLE_AUTO_COMPACT`, `DISABLE_COMPACT`, `/autocompact`, `--autocompact` — [model-config](https://code.claude.com/docs/en/model-config), [settings-reference](https://code.claude.com/docs/en/settings-reference), [env-vars](https://code.claude.com/docs/en/env-vars), [sub-agents](https://code.claude.com/docs/en/sub-agents) — **documented**
- **Idle compaction:** On interactive sessions using the 1-hour prompt cache TTL with auto-compaction enabled, Claude Code compacts idle conversations past `200,000` tokens (tunable via `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, floor `100000`) shortly before the cache expires; disable with `idleCompaction: false` (v2.1.290+). — **Setting / Env:** `idleCompaction`, `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` — [settings-reference](https://code.claude.com/docs/en/settings-reference), [env-vars](https://code.claude.com/docs/en/env-vars), [prompt-caching](https://code.claude.com/docs/en/prompt-caching) — **documented**
- **Manual `/compact`, `/clear`, `/rewind`, and session handoff:** `/compact [instructions]` replaces history with a summary (and `CLAUDE.md` can hold a `# Compact instructions` section), reloading `CLAUDE.md`, auto memory, and skills; `/clear [name]` resets context at zero token cost (and lets you `/resume` the old session later); `/rewind` truncates back to an already-cached prefix rather than paying to summarize. Anthropic recommends `/clear` between unrelated tasks or after two failed corrections, and saving durable state (markdown/JSON notes + git commits) for cross-session handoffs. — **Commands:** `/compact`, `/clear`, `/rewind`, `/rename`, `/resume` — [costs](https://code.claude.com/docs/en/costs), [prompt-caching](https://code.claude.com/docs/en/prompt-caching), [best-practices](https://code.claude.com/docs/en/best-practices), [effective-harnesses-for-long-running-agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) — **documented**
- **Context editing / tool-result clearing:** The Claude API exposes server-side Context Editing (`context-management-2025-06-27` beta) with `clear_tool_uses_20250919` (invalidates cache at the cleared point; use `clear_at_least`) and `clear_thinking_20251015`. Claude Code itself performs built-in tool-result clearing (referenced in `/usage` `Prompt cache (main)` as `"expected rebuild (compaction or tool-result clearing)"`), though no user-configurable Claude Code setting to tune tool-result clearing thresholds is documented in `settings-reference` or `env-vars`. — **API beta:** `context-management-2025-06-27` (`clear_tool_uses_20250919`, `clear_thinking_20251015`) — [context-editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [costs](https://code.claude.com/docs/en/costs) — **documented**
- **1M context window and >200K pricing:** Fable models, Opus 4.7+, Sonnet 5+, and Haiku 5.5 run with a **1M context window by default** (Opus 4.6 and Sonnet 4.6 require `[1m]`). Turn it off (capping sessions to 200K) with `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. Crucially, on the Anthropic API as of 2026-11-24, **Claude 4.6 and later models (except Haiku 5.5) have NO >200K long-context price surcharge** ("A 900k-token request is billed at the same per-token rate as a 9k-token request"); only **Haiku 5.5** steps up in price above **100,000** input tokens (`$0.10/$0.50` → `$0.50/$2.50` per MTok). — **Env:** `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` — [model-config](https://code.claude.com/docs/en/model-config), [pricing](https://platform.claude.com/docs/en/about-claude/pricing) — **documented**

### C. Prompt caching

- **Cache lifetimes and which plan gets which:** The API offers `5m` and `1h` ephemeral TTLs (each cache hit resets the timer). By default in Claude Code: on a **Claude subscription within plan usage**, the **main conversation** (interactive, `-p`, and Agent SDK turns) gets **1h**, while **everything else** (subagents, workflows, teammates, forks, compaction, titles) gets **5m**; on **usage credits, API keys, or cloud providers**, both buckets default to **5m**. Override with `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL`, `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`, `FORCE_PROMPT_CACHING_5M=1`, or `ENABLE_PROMPT_CACHING_1H=1`. — **Settings / Env:** `promptCacheTtl`, `subagentPromptCacheTtl`, `CLAUDE_CODE_PROMPT_CACHE_TTL`, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`, `FORCE_PROMPT_CACHING_5M`, `ENABLE_PROMPT_CACHING_1H` — [prompt-caching (Claude Code)](https://code.claude.com/docs/en/prompt-caching), [prompt-caching (API)](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) — **documented**
- **Exact API price multipliers (important update vs. older 0.1× assumptions):**
  - **Cache writes:** `1.25×` base input for 5m TTL (breaks even after 1 read); `2.0×` base input for 1h TTL (breaks even after 2 reads).
  - **Cache reads:** `0.025×` base input on **Fable 5.2 / 5.1** (`$0.20` / `$0.25` per MTok); `0.05×` base input on **Opus 5.5 / Sonnet 5.5** (`$0.20` / `$0.10` per MTok); `0.1×` on all other models (Opus 5/4.8/4.7/4.6, Fable 5, Sonnet 5/4.6, Haiku 5.5/4.5).
  - **Output:** `5×` base input across current models.
  — [pricing](https://platform.claude.com/docs/en/about-claude/pricing) — **documented**
- **What invalidates vs. preserves the cache:**
  - *Invalidates:* Switching models (`/model`, `opusplan` plan-mode toggles, automatic safety fallback, skill `model:` frontmatter); toggling `/fast` mode; adding/removing tool definitions or MCP servers **when tool search is off**; compacting (rebuilds conversation + project context; system prompt stays cached if current); hitting image/PDF limits (evicts a batch of oldest images, invalidating from the earliest edited message); upgrading Claude Code; changing thinking parameters; changing effort on older models (or Bedrock / Agent Platform / Claude apps gateway).
  - *Preserves:* Changing **effort level mid-session on Fable 5.1+, Opus 5.5, Sonnet 5.5, and Haiku 5.5** with an API key or Claude subscription; toggling Plan Mode (except under `opusplan`); invoking skills/commands (appended as messages); changing permission modes or output styles; editing repo files or `CLAUDE.md` mid-session; toggling `/advisor`; `/rewind`; spawning a subagent (parent cache unaffected); adding/removing MCP servers **while tool search is active**.
  — [prompt-caching (Claude Code)](https://code.claude.com/docs/en/prompt-caching), [prompt-caching (API)](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [prompt-caching blog](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) — **documented**
- **What an idle thread costs when it resumes:** Once inactivity exceeds the TTL (`5m` or `1h`), the next request—or a manual `/compact` run after expiry—misses the cache completely and re-processes and re-writes the entire context prefix at the cache-write rate (`1.25×` for 5m or `2.0×` for 1h, vs. `0.025×`–`0.1×` for a warm hit: a **12.5× to 80×** jump on that turn). — [prompt-caching (Claude Code)](https://code.claude.com/docs/en/prompt-caching), [costs](https://code.claude.com/docs/en/costs) — **documented**

### D. Subagents, delegation, effort, and parallel tool calls

- **Subagent cost and when to use one:** Each non-fork subagent starts with a fresh context and cannot read the parent's cache on turn 1 (whereas a `/subtask` fork or `/fork` session copy inherits the exact parent prefix and reads its cache). Anthropic's current Best Practices explicitly warn under *"What you can stop doing"*: *"Use subagents to protect your context window: Running out of context is rarely the problem anymore. Subagents are still great for parallel work, keeping noisy output out of your way, and independent review, but each of those costs extra tokens."* In Anthropic's multi-agent research study, single agents used **~4×** and multi-agent systems **~15×** the tokens of chat; Claude Code docs also note Agent Teams in plan mode use **~7×** a standard session. — **Commands / Env:** `/subtask`, `/fork`, `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default `3`), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default `20`), `omitClaudeMd: true` — [sub-agents](https://code.claude.com/docs/en/sub-agents), [best-practices](https://code.claude.com/docs/en/best-practices), [costs](https://code.claude.com/docs/en/costs), [prompt-caching](https://code.claude.com/docs/en/prompt-caching), [multi-agent-research-system](https://www.anthropic.com/research/multi-agent-research-system) — **documented** (4×, 7×, 15×: **measured**)
- **Per-agent model and effort selection:** Set `model` and `effort` in subagent frontmatter or programmatic `AgentDefinition`, or set a default/forced model across all subagents with `CLAUDE_CODE_SUBAGENT_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (v2.1.257+; does not override forks or `model: inherit` skills). Built-in `Explore` defaults to Opus when the parent runs Fable on Anthropic API/subscriptions (override by defining a custom `Explore` subagent with `model: haiku`). — **Env / Frontmatter:** `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `model:`, `effort:`, `autoCompactWindow:` — [sub-agents](https://code.claude.com/docs/en/sub-agents), [model-config](https://code.claude.com/docs/en/model-config) — **documented**
- **Token cost of effort and thinking levels:** Thinking tokens are billed as **output tokens** (`5×` input) even when collapsed/redacted, and on Fable models, Opus 5.5, Sonnet 5.5, and Haiku 5.5 thinking **cannot be turned off** (`alwaysThinkingEnabled: false` and `MAX_THINKING_TOKENS=0` are ignored); `effort` (`low`, `medium`, `high`, `xhigh`, `max`) is the primary control and affects thinking, response text, and tool call volume. Opus 5.5 and Fable 5.2 default to `medium` in Claude Code (Anthropic reports Opus 5.5 at `medium` matches/exceeds Opus 5 at `high`); in Anthropic's Terminal-Bench / build tests, `low` → `medium` → `high` → `max` scaled runtime and spend sharply (e.g., 1.5m → 4m → 11m → 67m on an underspecified build; 16m → 22m → 33m → 79m on a specified build), and `max` is flagged as *"prone to overthinking"* with diminishing returns. Cap effort with `maxEffortLevel` (global or per-model in `modelSettings`). — **Settings / Env / Flags:** `effortLevel`, `modelSettings.<m>.effortLevel`, `maxEffortLevel`, `CLAUDE_CODE_EFFORT_LEVEL`, `--effort`, `/effort`, `alwaysThinkingEnabled`, `MAX_THINKING_TOKENS` (legacy fixed-budget models only) — [model-config](https://code.claude.com/docs/en/model-config), [effort](https://platform.claude.com/docs/en/build-with-claude/effort), [spending-your-effort](https://claude.dev/blog/spending-your-effort/) — **documented** (runtimes/pass rates: **measured**)
- **Parallel tool calls and Code Mode:** Batching independent tool calls in one assistant turn eliminates extra full-context API round-trips (each skipped turn avoids re-reading the entire prompt cache). Anthropic's parallel-tool-use docs provide an explicit `<use_parallel_tool_calls>` prompt block and note that **Fable 5.1+ can issue fewer parallel calls in long agent loops unless prompted to batch**. Experimental **Code Mode** (v2.1.323+, off by default) lets Claude write JS to execute multiple tool calls in one step, and API Programmatic Tool Calling cut average tokens by **37%** (`43,588` → `27,297`) on complex research tasks. — [parallel-tool-use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use), [code-mode](https://code.claude.com/docs/en/code-mode), [advanced-tool-use](https://www.anthropic.com/research/advanced-tool-use) — **documented** (37% PTC saving: **measured**)

### E. Usage limits on subscription plans

- **How weekly and 5-hour limits work:** Paid plans share limits across claude.ai, Claude Desktop, and Claude Code. Pro and Max have a rolling **5-hour session limit** plus a **weekly limit** (fixed weekly reset assigned to the account); **verified Ultra accounts have no 5-hour limit** (weekly limit only). Max and Ultra plans also have a **separate weekly limit for Fable**. Usage consumption depends on conversation length/complexity, features/tools used, model choice, and effort level—Anthropic does **not** publish exact token quotas or model weighting formulas. — [use-claude-code-with-your-pro-max-or-ultra-plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan), [how-do-usage-and-length-limits-work](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work), [feature-availability](https://code.claude.com/docs/en/feature-availability) — **documented**
- **Whether cache reads count against subscription limits:** **Yes, at a reduced weight.** Both `costs.md` (*"With prompt caching, Claude Code re-reads that history at the cached token rate, so a one-line question in a session that has been open all day still draws usage for the whole conversation"*) and `support.claude.com` (*"cached portions count less against your limits than new content"* / *"after a long break, your first message counts that content in full again"*) confirm that cache reads draw on plan limits, just much less per token than uncached reads or cache writes. — [costs](https://code.claude.com/docs/en/costs), [usage-limit-best-practices](https://support.claude.com/en/articles/9797557-usage-limit-best-practices) — **documented**
- **Official monitoring tools:**
  - **`/usage`** (and aliases **`/cost`**, **`/stats`**): Shows session estimated cost, per-model token counts (`input`, `output`, `cache read`, `cache write`), `Prompt cache (main)` hit ratio/misses/likely cause/warm-or-cold status (v2.1.251+/260+), plan usage bars, and **Plan usage breakdown** (24h/7d attribution to skills/subagents/plugins/MCP servers, loops, and actionable recommendations with `f` to fix on v2.1.305+).
  - **Status line JSON (`/statusline`):** Exposes `context_window.{used_percentage, remaining_percentage, context_window_size, total_input_tokens, total_output_tokens, current_usage}`, `exceeds_200k_tokens`, `cost.total_cost_usd`, `effort.level`, `fast_mode`, `prompt_cache`, and `rate_limits.{five_hour, seven_day}.{used_percentage, resets_at}`.
  - **OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1`):** Exports `claude_code.token.usage` (broken down by `type`: `input`, `output`, `cacheRead`, `cacheCreation`, plus `model`, `skill.name`, `plugin.name`, `agent.name`), `claude_code.cost.usage`, `claude_code.session.count`, `claude_code.plugin_loaded`, and `claude_code.skill_activated`.
  — [costs](https://code.claude.com/docs/en/costs), [commands](https://code.claude.com/docs/en/commands), [statusline](https://code.claude.com/docs/en/statusline), [monitoring-usage](https://code.claude.com/docs/en/monitoring-usage), [plugins/measure](https://code.claude.com/docs/en/plugins/measure) — **documented**

### F. Official cost & context-engineering guidance

- **Anthropic's "Manage costs effectively" (`costs.md`):** Recommends (1) `/clear` between unrelated tasks and `/compact` with custom instructions (`# Compact instructions` in `CLAUDE.md`), (2) choosing smaller models for routine work and Haiku/Sonnet for subagents/teammates, (3) preferring CLI tools (`gh`, `aws`, `gcloud`) over MCP servers and disabling unused servers via `/mcp`, (4) installing code-intelligence (LSP) plugins to avoid multi-file grep/read loops, (5) filtering noisy tool/test output with `PreToolUse` hooks (e.g., piping test runs to `tail -n 100`), (6) keeping `CLAUDE.md` under 200 lines and moving specialized workflows into on-demand skills, (7) lowering effort for simpler tasks, (8) offloading verbose log/test runs to subagents, (9) turning off background burn (prompt suggestions, idle goal check-ins via `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`, idle sessions/loops), and (10) using Plan Mode, specific prompts, and `/rewind` to avoid rework. — [costs](https://code.claude.com/docs/en/costs) — **documented**
- **Anthropic engineering posts on context engineering:**
  - *Effective context engineering for AI agents*: Target the *"smallest set of high-signal tokens"* to fight **context rot** (attention stretches across $n^2$ pairwise relationships); favor just-in-time retrieval (glob/grep) over preloading; combine compaction, clearing stale tool results, structured external note-taking, and isolated subagents. — [effective-context-engineering-for-ai-agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) — **documented / opinion**
  - *Effective harnesses for long-running agents*: Compaction alone fails on multi-window builds; use an initializer/worker split with durable JSON feature lists, `init.sh`, and git-committed checkpoints so every fresh session recovers state cheaply. — [effective-harnesses-for-long-running-agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) — **documented / measured**
  - *Multi-agent research system*: Embed explicit effort/tool-call scaling rules in prompts (1 agent / 3–10 calls for simple lookup vs. multi-agent only for parallel breadth); write large subagent outputs directly to files to avoid coordinator "game of telephone" bloat. — [multi-agent-research-system](https://www.anthropic.com/research/multi-agent-research-system) — **documented / measured**
  - *Prompt caching is everything*: Order prefixes strictly static-first (`system + tools` → `CLAUDE.md` → `session context` → `messages`), inject updates via `<system-reminder>` messages rather than editing the system prompt, never swap models or add/remove upfront tools mid-session, and use subagents to hand off work to cheaper models. — [prompt-caching blog](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) — **documented**

### G. T3 Code (`pingdotgg/t3code`)

- **How T3 Code launches Claude Code (from `ClaudeAdapterV2.ts`):** T3 Code drives Claude Code via the Claude Agent SDK (`query()`), passing:
  - `systemPrompt: { type: "preset", preset: "claude_code", append: ... }` (appends T3 runtime, orchestration, `t3_background_wait`, `send_to_user`, and device instructions plus any user `--append-system-prompt` / `--append-system-prompt-file` launch args).
  - `tools: { type: "preset", preset: "claude_code" }` (or a restricted list such as `["Read", "Glob", "Grep"]` when policy restricts tools), `allowedTools`, `disallowedTools`, and `mcpServers` (T3's own MCP tools).
  - `settingSources`: `["user", "project", "local"]` by default (or `["project", "local"]` when using a custom home).
  - `model` and `effort` per thread from the composer/project model selection, plus `thinking: { type: "adaptive", display: "summarized" }` and `showThinkingSummaries: true` unless disabled via `--thinking-display omitted`.
  - `title` passed directly (skipping Claude Code's redundant session-title model request), and `promptSuggestions: false` automatically on delegated child threads (while interactive threads follow the user's setting).
  - **Automatic tool-search override:** `claudeToolSearchOverride()` forces `ENABLE_TOOL_SEARCH="true"` in SDK flag settings whenever the user's env uses `auto` or `auto:N` (`0 < N < 100`), specifically because T3's MCP schemas would otherwise fall below the 10% threshold on 1M-context models and load upfront!
  - **Delegated child TTL gotcha (huge finding):** Because a T3 delegated child thread is its own Agent SDK session, Claude Code treats it as a *main conversation* (giving it **1h TTL** on subscriptions unless overridden). `claudeQueryEnvironment()` explicitly checks the user's Claude `subagentPromptCacheTtl` setting and copies it into `CLAUDE_CODE_PROMPT_CACHE_TTL` for delegated child threads (`lineage.relationshipToParent === "subagent"`). On resumed sessions, T3 also sets `MCP_CONNECTION_NONBLOCKING="0"` so MCP servers finish connecting before turn 1.
  — [ClaudeAdapterV2.ts](https://github.com/pingdotgg/t3code/blob/main/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts) — **documented (source-verified)**
- **T3 Code UI controls for context, compaction, models, and presets:**
  - **Auto-compact after** (Claude provider settings): Integer `100000`–`1000000` (e.g., `300000`); T3 passes both `autoCompactWindow` and `CLAUDE_CODE_AUTO_COMPACT_WINDOW`.
  - **Compact idle threads** (**Settings > Providers > Advanced**, overridable per Claude instance; applies to threads >200K tokens): `When you return` (default — shows a **Compact** chip next to Send after cache expiry), `Before the cache expires (beta)` (sends `/compact` automatically shortly before the 1h/5m cache expires while still cached), or `Never`.
  - **Separate Claude instances / presets (`CLAUDE_CONFIG_DIR`):** Add multiple Claude provider instances with different `CLAUDE_CONFIG_DIR`, **Environment variables**, and **Launch arguments** (e.g., `--settings`, `--append-system-prompt-file`, `--plugin-dir`)—useful for maintaining a lean "no-bloat" Claude profile for high-volume/delegated work.
  - **Per-project model & effort defaults + Usage dashboard:** Projects can override default provider/model/effort; **Usage** (`mod+u`) aggregates token counts, cache hit rates, and pooled subscription limits across accounts.
  — [providers-claude.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/providers-claude.md), [composer.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/composer.md), [usage.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/usage.md), [claudeCompaction.ts](https://github.com/pingdotgg/t3code/blob/main/packages/shared/src/claudeCompaction.ts) — **documented**

## 3. Top 10 Expected Savings for the Measured Profile

**Baseline calibration from the profile (using the user's weights: input `1`, cache write `1.25`, cache read `0.1`, output `5`):**
- `4.4B` cache-read tokens × `0.1` = `440M` weighted units (`53%` of total) → **Total weekly weighted volume `W ≈ 830M` units**.
- Cache writes (`22%`): `183M` units → **`~146M` cache-write tokens/week** (consistent with `31M` tool results + `41.5M` output + `~42M` child-agent startups + `~33M` idle rewrites).
- Output (`25%`): `208M` units → **`~41.5M` output tokens/week** (`~1,930` output tok/req).
- **Important pricing caveat:** On current Anthropic API pricing ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)), 1-hour cache writes cost **`2.0×`** (not `1.25×`), while Opus 5.5 cache reads cost **`0.05×`** and Fable 5.1/5.2 cache reads cost **`0.025×`** (not `0.1×`). Under current API rates, **output/thinking, cache writes, and cold-starting 600 child agents carry an even larger share of real cost** than the `0.1×`-read formula shows.

Estimates below are **standalone** against the baseline; several overlap multiplicatively (applying all 10 realistically compounds to roughly **~55%–70%** total reduction, not their raw sum).

## 4. Unverified Items & Widely Repeated Claims Lacking Primary Sources

### Could not verify from primary sources
1. **Exact subscription-plan quota formula:** Anthropic does not publish exact weekly token caps, the exact ratio between cache reads / cache writes / output tokens inside Pro/Max/Ultra subscription meters, or the exact quota multiplier between Haiku, Sonnet, Opus, and Fable (beyond confirming that model choice, effort, length, and cached vs. uncached tokens all affect limits, and that Fable has a separate weekly cap on Max/Ultra).
2. **User-facing tuning for Claude Code's built-in tool-result clearing:** `/usage` (`costs.md`) explicitly confirms Claude Code performs internal tool-result clearing ("compaction or tool-result clearing"), and the Messages API documents `clear_tool_uses_20250919`, but no `settings.json` key or environment variable to configure Claude Code's built-in tool-result clearing threshold is documented in `settings-reference.md` or `env-vars.md`.
3. **Exact token size of the irreducible built-in Claude Code system prompt + core tool schemas:** `context-window.md` gives illustrative numbers (e.g., `4,200` tokens for system prompt), while `pricing.md` documents the small API-level tool-use system prompt (`286` tokens on Opus 5.5 / Sonnet 5.5), but Anthropic does not publish an official fixed token breakdown for Claude Code's complete built-in prompt + core tool schemas (the `~35K–40K` remainder in the user's measurement).

### Widely repeated claims that are outdated or unsupported by primary sources
1. **"Requests over 200K tokens cost 2× input / 1.5× output on 1M-context Claude models."** — **Outdated / false for current models.** Per `platform.claude.com/docs/en/about-claude/pricing` (opened 2026-11-24), Claude 4.6 and later models (Opus 4.6–5.5, Sonnet 4.6–5.5, Fable 5–5.2) have **flat standard pricing across the full 1M context window**; only **Haiku 5.5** has a long-context tier, and its threshold is **100K**, not 200K.
2. **"Cache reads are always 0.1× (90% off) on all Claude models."** — **Outdated.** On current API pricing, cache reads are **0.05×** (95% off) on Opus 5.5 and Sonnet 5.5, and **0.025×** (97.5% off) on Fable 5.1 and Fable 5.2; `0.1×` applies to older models and Haiku.
3. **"Cache reads are free / don't count toward Pro/Max/Ultra subscription limits."** — **False.** Anthropic explicitly states on both `code.claude.com/docs/en/costs` and `support.claude.com` (`9797557`) that cached reads still draw on subscription limits, just at a lower weight than uncached content. (The "free" confusion comes from API **TPM/RPM rate limits**, where `platform.claude.com` notes cache hits are not deducted against ITPM rate limits.)
4. **"Changing effort level mid-session always breaks the prompt cache."** — **Outdated on current models.** Per `code.claude.com/docs/en/prompt-caching`, changing effort preserves the prompt cache by default on **Fable 5.1+, Opus 5.5, Sonnet 5.5, and Haiku 5.5** on Anthropic API keys and Claude subscriptions (though it still invalidates on older models, Bedrock, Agent Platform, and Claude apps gateway).
5. **"Use `alwaysThinkingEnabled: false` or `MAX_THINKING_TOKENS=0` to turn off thinking on Opus 5.5 / Fable."** — **False.** Per `code.claude.com/docs/en/model-config`, thinking cannot be disabled on Opus 5.5, Sonnet 5.5, Haiku 5.5, or Fable models; both settings are ignored and only `effort` controls reasoning depth.
6. **"Set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=95` to delay compaction, or `SLASH_COMMAND_TOOL_CHAR_BUDGET` defaults to 15,000 / 2%."** — **Inaccurate.** `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` can only *lower* the trigger below default (higher values are ignored), and the documented current default for skill listing budget is **1% of context window** (`skillListingBudgetFraction: 0.01`, fallback 8,000 chars), not 2% / 15,000.
7. **"Always spawn subagents to save tokens / protect the context window."** — **Contradicted by Anthropic's own docs.** `best-practices.md` explicitly puts *"Use subagents to protect your context window"* under *"What you can stop doing"*—noting subagents cost extra tokens (cold prefix + separate loop) and should be reserved for parallelism, isolating noisy output, or independent review.
