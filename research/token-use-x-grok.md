# Cutting token use in agent threads: what people post on X

Raw research result, saved as returned on 2026-11-24. Researcher: grok-4.7. Not edited. Claims found only on X are opinion until another source backs them.

---

X search worked. I read about 90 posts and opened 15 threads. Nothing below is from memory. Each finding is marked shown (the post includes a count, a config, or a screenshot) or opinion.

## B. Context growth inside a thread

**Every turn resends the whole session, so cost grows with the square of length even when the cache hits.** "Input token costs are O(n^2)… even cache hits can get pricey." Shown as the mechanism, not a personal bill. [https://x.com/KentonVarda/status/2035805123297808511](https://x.com/KentonVarda/status/2035805123297808511) @KentonVarda, 22 Mar 2026. "55 to 85 percent of a long Claude Code session's token spend was the agent re-reading its own history… double the length… roughly quadruple what gets re-read." Shown as someone else's measurement, relayed. [https://x.com/stretchcloud/status/2124169213791072630](https://x.com/stretchcloud/status/2124169213791072630) @stretchcloud, 21 Nov 2026. One team week: of $960 called avoidable, "$360" was "history resent past 200k." Shown (screenshot of their scan). [https://x.com/dannygnc/status/2124310666458902988](https://x.com/dannygnc/status/2124310666458902988) @dannygnc, 22 Nov 2026.

**The 1M window lets a thread get expensive and, some say, worse.** A post aimed at T3 Code says Claude Code there "defaults to 1M context and no auto compaction," and that setting `"CLAUDE_CODE_AUTO_COMPACT_WINDOW": "300000"` plus T3's "Providers → Advanced → Compact Idle Thread" gave "up to 20% more Claude usage a week." Shown (screenshot). [https://x.com/lucastohdev/status/2124809609068327249](https://x.com/lucastohdev/status/2124809609068327249) @lucastohdev, 23 Nov 2026. A reply the next day: "Misinformation. Autocompaction works out of the box in t3code for both: Claude and Codex." Opinion, no counter-screenshot. [https://x.com/atarutin/status/2125119222397161510](https://x.com/atarutin/status/2125119222397161510) @atarutin, 24 Nov 2026. "1M with no compaction sounds like a trap." Opinion. [https://x.com/surlymochan/status/2124810289392791987](https://x.com/surlymochan/status/2124810289392791987) @surlymochan, 23 Nov 2026. "Once a session passes 800K tokens, every message re-reads the whole thing, so one message costs as much as opening 8 new sessions." Shown as a relayed measurement. [https://x.com/Voxyz_ai/status/2124246472883601720](https://x.com/Voxyz_ai/status/2124246472883601720) @Voxyz_ai, 21 Nov 2026. Quality claim, no numbers of his own: "Claude's 1M context window starts rotting after 200k tokens." Opinion. [https://x.com/birdabo/status/2038602968497549671](https://x.com/birdabo/status/2038602968497549671) @birdabo, 30 Mar 2026.

**Handoff file, then `/clear`, beats waiting for auto-compact.** Write what is done, in progress, and left, `/clear`, then read that file plus the git diff. Opinion. @surendartwt, 22 Nov 2026. Same shape as a 40-line STATE.md and a switch at 200k. @Voxyz_ai, 21 Nov 2026. "Set CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50." Opinion, no before/after. @sufyanbuild. "`/clear` after every finished task." Opinion. @mardybum9878. "`/clear` … above 400k." Opinion. @EXM7777. Compact at task boundaries rather than a fixed count. Opinion plus a repo link. [https://x.com/lbzepoqo/status/2125130290662441275](https://x.com/lbzepoqo/status/2125130290662441275) @lbzepoqo, 24 Nov 2026.

**Large tool output should not land in the main thread.** "Every image analysis runs in a subagent, which gives me back only text." Opinion, written as a rule. @Voxyz_ai, 21 Nov 2026. "Before reading a whole file, grep first and only read the parts you need." Opinion. [https://x.com/Voxyz_ai/status/2119535433969500172](https://x.com/Voxyz_ai/status/2119535433969500172) @Voxyz_ai, 8 Nov 2026. "Letting noisy commands dump logs into context" is listed as a mistake; hand the job to a subagent so only the answer returns. Opinion, describing a workshop. [https://x.com/RRRangle/status/2124201044498690557](https://x.com/RRRangle/status/2124201044498690557) @RRRangle, 21 Nov 2026. Code Mode on one search task: 815k → 331k tokens, 10 → 6 round trips, because a script filtered before the results entered context. It also missed 4 findings. Shown, one pair of runs. @Tornikenizh, 18 Nov 2026. The April audit counted 1,122 reads of a file already read 3 or more times, one file read 33 times. Shown, secondhand. @om_patel5, 6 Apr 2026.

## C. Subagents and delegation

**A subagent saves the parent only if the parent would otherwise have held the dumps.** Exploration and review in a side window, summary comes back. Opinion. @EXM7777. @surendartwt also says the opposite risk: "Your 10 specialized subagents might be slowing you down… delegating work adds overhead." Opinion.

**Parallel cold subagents do not share a cache.** Same tiny task, Opus, three subagents in one message: each wrote about 126k tokens of fresh cache. The same three inside a workflow staggered by 1–2 seconds: agents 2 and 3 read about 113k and wrote about 13k. At API weights (write 1.25x, read 0.1x) the workflow's input cost was about 45% of the parallel run. Shown, one run each, and he says the 45% is a direction because Anthropic does not publish how the subscription weighs cache reads. [https://x.com/noname_nonce/status/2125169945759940759](https://x.com/noname_nonce/status/2125169945759940759) @noname_nonce, 24 Nov 2026.

**Effort is inherited, and that is what burned limits.** After reading user session ids, Boris: no single regression; the fast burn was "one or two heavy sessions (xhigh effort, /goal, Workflows, Agent Teams, long SDK jobs)… Subagents inherit it by default and it can add up fast." Shown as Anthropic's read of those sessions. @bcherny, 28 Oct 2026. You can now ask for a lower effort on a subagent without changing the session, and `ultrathink` raises effort for one turn only. [https://x.com/ClaudeDevs/status/2117670661221134775](https://x.com/ClaudeDevs/status/2117670661221134775) @ClaudeDevs, 3 Nov 2026. "Do not use Sonnet with max effort… in Claude Code the default is medium." [https://x.com/edwinarbus/status/2104675431853248816](https://x.com/edwinarbus/status/2104675431853248816) @edwinarbus, 28 Sep 2026. A reply: Opus high with Sonnet subagents "felt really great" for parallel fixes. Opinion. [https://x.com/mweinbach/status/2104690274270101804](https://x.com/mweinbach/status/2104690274270101804) @mweinbach, 28 Sep 2026. `CLAUDE_CODE_SUBAGENT_MODEL` routes every subagent to another model. Opinion, no measurement. [https://x.com/mehdidotnet/status/2115931081128219113](https://x.com/mehdidotnet/status/2115931081128219113) @mehdidotnet, 29 Oct 2026. "If a subagent can do the job on low effort, the job probably didn't need a subagent." Opinion. [https://x.com/AIQuanting/status/2115964735971811808](https://x.com/AIQuanting/status/2115964735971811808) @AIQuanting, 30 Oct 2026.

**Brief the child with the files and the question, not the parent's history.** A reviewer file that allows only Read, Grep, and Glob, model Sonnet, "Review only the files you're given." Opinion, a template. [https://x.com/Rajesh7113/status/2123309549121585446](https://x.com/Rajesh7113/status/2123309549121585446) @Rajesh7113, 19 Nov 2026.

**Status updates were a quiet tax, then cut.** "A running subagent updates its status line every 30 seconds, and each update used to re-read its whole conversation. Now Haiku 5.5 writes it from short notes… about 99% less." Sessions with background subagents then "used about 5% less of the limit." Shown as Anthropic's own before/after, v2.1.316+. [https://x.com/ClaudeDevs/status/2118063143167693011](https://x.com/ClaudeDevs/status/2118063143167693011) @ClaudeDevs, 4 Nov 2026 and [https://x.com/ClaudeDevs/status/2118063144572772627](https://x.com/ClaudeDevs/status/2118063144572772627) @ClaudeDevs, 4 Nov 2026.

**More concurrency can cost more and solve less.** "Solve rates collapse from 83% to 59%… 3.3x more tokens." Shown as a figure in the post, the underlying benchmark is not in the text. [https://x.com/Decoded08/status/2124420645744422994](https://x.com/Decoded08/status/2124420645744422994) @Decoded08, 22 Nov 2026.

## D. Prompt caching

**Two TTLs, and the write price differs.** 5-minute write is 1.25x input, read is 0.1x, so the second call already wins (1.35x vs 2x). The 1-hour write is 2x, so it needs a third call. Shown as list-price arithmetic. [https://x.com/0xpiyushvm/status/2125112931545190428](https://x.com/0xpiyushvm/status/2125112931545190428) @0xpiyushvm, 24 Nov 2026. Valid subagent values are `5m` or `1h`, not `60`. [https://x.com/Kulshekhar/status/2108910947691831793](https://x.com/Kulshekhar/status/2108910947691831793) @Kulshekhar, 10 Oct 2026. Dan's correction: `"subagentPromptCacheTtl": "1h"`. [https://x.com/daniel_mac8/status/2108912192338673737](https://x.com/daniel_mac8/status/2108912192338673737) @daniel_mac8, 10 Oct 2026.

**Interactive Claude Code defaults to 1 hour. Agent-SDK-shaped work defaults to 5 minutes because 1 hour costs more on average.** Boris: "API is usually used for Agent SDK shaped workloads, where 1h TTL would result in higher costs on average, so we stick to 5m to be safe. Interactive usage defaults to 1h because that is cheaper for people on average." [https://x.com/bcherny/status/2108768259516281038](https://x.com/bcherny/status/2108768259516281038) @bcherny, 10 Oct 2026. Dan then ran a script on his own subagent history and switched back to 5m. Shown (video plus script). [https://x.com/daniel_mac8/status/2108971441102172620](https://x.com/daniel_mac8/status/2108971441102172620) @daniel_mac8, 10 Oct 2026. Another user's split: about 1% of pauses (long builds, polls, resumes) caused nearly half of subagent cache writes; a blanket 60-minute cache saved about 5% overall but made about 80% of sessions more expensive. Shown as his historical replay. [https://x.com/Alpaca_Capital/status/2108789031953985549](https://x.com/Alpaca_Capital/status/2108789031953985549) @Alpaca_Capital, 10 Oct 2026.

**Coming back after the TTL is the expensive moment.** One month, 110 sessions, 46,580 turns: "While you're working, it costs 1x. After coffee, 1.3x. After a call, 1.6x. After lunch: 13x… A new session costs 4.5x." So summarize, then paste into a fresh window, rather than continue a dead cache. Shown. [https://x.com/quxiaoyin/status/2085408811104534754](https://x.com/quxiaoyin/status/2085408811104534754) @quxiaoyin, 6 Aug 2026. A week from another team: cache rebuilt after idle breaks was $532 of $960 avoidable, against $68 for failed tool calls. Shown. @dannygnc, 22 Nov 2026, and [https://x.com/dannygnc/status/2124964557483618797](https://x.com/dannygnc/status/2124964557483618797) @dannygnc, 23 Nov 2026. Since 3 Nov, Claude Code "compacts long idle sessions right before the prompt cache expires (~1h)," and Pro/Max warns if resuming would take a big piece of the 5-hour limit. [https://x.com/ClaudeDevs/status/2117670659715375344](https://x.com/ClaudeDevs/status/2117670659715375344) @ClaudeDevs, 3 Nov 2026.

**What breaks the prefix.** From a read of Thariq's writeups: timestamps in the static prompt, shuffling tools, adding or removing tools mid-session, switching models mid-conversation. Plan mode keeps every tool loaded and uses EnterPlanMode/ExitPlanMode so the prefix stays. Compaction forks with the same prefix. Switching Opus to Haiku inside the session "is actually more expensive" because the cache rebuilds. Use a subagent and a handoff instead. Opinion as a summary of those articles, no new measurement. [https://x.com/rohit4verse/status/2035409223740428646](https://x.com/rohit4verse/status/2035409223740428646) @rohit4verse, 21 Mar 2026. Same warning from the workshop notes: switching model or effort mid-session breaks the cache. Opinion. @RRRangle, 21 Nov 2026.

An April post claimed two binary bugs (a billing-string replacement, and `--resume` moving tool attachments) forced full rebuilds. Shown only as a claim with a screenshot, widely quoted, and I did not find a later confirmation that those bugs still exist. [https://x.com/om_patel5/status/2038754906715066444](https://x.com/om_patel5/status/2038754906715066444) @om_patel5, 30 Mar 2026.

## G. Disagreements and things that backfired

**Setting every subagent to a 1-hour cache backfired for the person who popularized it.** Dan's morning post said dollars were "flying out the window" at 5 minutes. The same day his script said 1 hour would not save him, and he switched back. @daniel_mac8, 10 Oct 2026, both posts above. Boris's reason matches a delegated-agent workload: 1 hour is more expensive on average there. Alpaca's replay says a blanket 1 hour made most sessions worse and only the long waits paid.

**Code Mode cut tokens and missed bugs.** 815k to 331k, and 4 unused-code findings only the normal run caught. @Tornikenizh, 18 Nov 2026.

**T3's 1M default is asserted and denied.** Lucas says no auto-compact and a 300k window plus "Compact Idle Thread" is worth about 20%. Andrei says auto-compact already works. Both 23–24 Nov 2026, links above. I cannot settle it from the posts.

**"Switch to Sonnet after Opus has set the pattern" fights the cache.** That trick is posted with a screenshot of a compact-then-switch. [https://x.com/OrganicGPT/status/2124726926589800944](https://x.com/OrganicGPT/status/2124726926589800944) @OrganicGPT, 23 Nov 2026. The caching writeups say a model change rebuilds the prefix and can cost more than staying put. @rohit4verse, @RRRangle.

**The April "5-minute idle is 54% of turns and a 10x jump" audit may describe an older default.** @om_patel5, 6 Apr 2026. By October Boris said interactive use defaults to 1 hour, and by 3 Nov idle sessions are compacted just before that hour. The shape (idle gap, then a full rewrite) is still the waste Danny and Xiaoyin measured later.

**More agents is not cheaper.** Specialized fleets add overhead (@surendartwt). Parallel launches each pay a full cache write (@noname_nonce). One chart shows solve rate 83% to 59% at 3.3x tokens (@Decoded08).

**A huge instruction file gets ignored and still gets paid.** @EXM7777 and @surendartwt. I found no post that measured a 16 KB global file specifically.

## The 10 changes most likely to cut this profile

Ordered for a week where two-thirds of the cost sits in prompts over 200k, threads run for hundreds of turns, cache reads are half the bill, and screenshots and file dumps are large.

1. **End or compact a thread around 150–200k, and do not let one thread run for hundreds of turns.** This is the quadratic re-read. A handoff file plus `/clear` is the habit people trust more than waiting until the window is full. @KentonVarda 22 Mar 2026, @dannygnc 22 Nov 2026, @Voxyz_ai 21 Nov 2026, @surendartwt 22 Nov 2026, @stretchcloud 21 Nov 2026.

2. **Keep screenshots and whole-file dumps out of the parent.** One 40k image or 13k file is re-read on every later turn. Run vision and wide searches in a subagent, or in a script that returns a short result. Grep, then read a range. @Voxyz_ai 21 Nov 2026 and 8 Nov 2026, @Tornikenizh 18 Nov 2026, @om_patel5 6 Apr 2026, @RRRangle 21 Nov 2026.

3. **Compact parked threads before the cache dies.** Two separate week-long scans put idle rebuilds ahead of failed tool calls. On current Claude Code that compact is supposed to happen just before the hour. In a multi-thread app, turn on the idle-thread compact if it is actually off. @quxiaoyin 6 Aug 2026, @dannygnc 22–23 Nov 2026, @ClaudeDevs 3 Nov 2026, @lucastohdev 23 Nov 2026.

4. **Cut the 73k that arrives before the first word.** Fresh `/context`, then `/doctor`, then disable the MCP servers and plugins that repo does not need, and mark rare skills manual-only. Shorten the global instruction file and point at docs instead of inlining them. That prefix is on every turn of every thread. @daniel_mac8 21 Aug 2026, @Tornikenizh 18 Nov 2026, @dsp_ 23 Mar 2026, @om_patel5 6 Apr 2026, @EXM7777 11 Aug 2026, @bcherny 12 Oct 2026.

5. **Stop review-fix loops at 3 rounds and hand the next round what was already accepted or rejected.** Anthropic's own numbers: 50+ rounds on one PR, then 8.9% to 1.5% of PRs needing 5 or more. @davekiss and @ClaudeDevs 16 Oct 2026, @bug_d3v 18 Nov 2026.

6. **Do not let mechanical subagents inherit Fable or xhigh.** Say the effort in the brief, or set a cheaper model on those children. Boris traced real limit burns to inherited effort, workflows, and agent teams. @bcherny 28 Oct 2026, @ClaudeDevs 3 Nov 2026, @edwinarbus 28 Sep 2026.

7. **Do not start a crowd of subagents in one message.** Each cold one writes a full prompt cache. Start one, then the rest, or stagger them so the prefix hits. @noname_nonce 24 Nov 2026.

8. **Leave delegated subagents on the 5-minute cache unless your logs show long idle gaps.** A blanket 1 hour is the setting Boris says costs more for SDK-shaped work, and the setting Dan measured and reverted. @bcherny 10 Oct 2026, @daniel_mac8 10 Oct 2026, @Alpaca_Capital 10 Oct 2026.

9. **Do not change model or effort in the middle of a hot thread.** That rebuilds the prefix you are already paying to re-read. Start a new session or a subagent for the other model. @rohit4verse 21 Mar 2026, @RRRangle 21 Nov 2026.

10. **Read `/usage` after a heavy session and run ccusage on the week.** The in-product view names the plugin, skill, or effort that dominated. ccusage is what people use to compare days from local logs. Update past v2.1.316 so background status lines are the cheap Haiku notes, not a full re-read every 30 seconds. @ClaudeDevs 3 Nov 2026 and 4 Nov 2026, @bcherny 28 Oct 2026, @0xGhostyx 22 Nov 2026.
